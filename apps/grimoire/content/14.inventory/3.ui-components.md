All inventory UI ships from the engine's UI layer. Components are dumb. They read from `useGameStore` queries and emit events for the container page to wire up.

```ts
import {
  CharacterInventoryModal,
  CharacterPreview,
  CharacterPreviewModel,
  EquipmentSlot,
  BagGrid,
  ItemCell,
  ItemTooltip,
  ItemContextMenu,
  WeightBar,
  LootPopover,
  WorldItem,
  PortraitDropZone,
} from '@artificer-forge/engine/ui'
```

::note
The code samples below use the `Inventory`-prefixed tags (`<InventoryBagGrid>`, etc.) that auto-import resolves to in a consuming app. When importing from the engine directly, use the unprefixed names from the block above.
::

## Component Tree

```
CharacterInventoryModal                 # the UModal shell
├── EquipmentSlot × N                   # one per slot, around the doll
├── CharacterPreview                    # mini TresCanvas, resolves rig + equipment
│   ├── CharacterPreviewModel           # GLB characters: useGLTF + useEquipment + idle anim
│   └── ModularCharacterPreviewModel    # `appearance` characters: useModularRig + useModularArmor
├── BagGrid                             # the right-side grid
│   ├── ItemCell × items                # draggable cells, render item.icon
│   └── WeightBar                       # weight / capacity bar
ItemTooltip                             # hover tooltip with icon "popping out"
ItemContextMenu                         # right-click dropdown (singleton)
LootPopover                             # external — for chests/corpses
WorldItem                               # external — for items on the ground
PortraitDropZone                        # wraps party portraits as drop targets
```

::note
`ModularCharacterPreviewModel` is internal: `CharacterPreview` imports it directly and `ui/index.ts` does not export it. Use `CharacterPreview` and let it pick the model component.
::

## CharacterInventoryModal

The modal shell. Opens whenever `useInventory().isOpen` is true and renders the focused character.

```vue
<CharacterInventoryModal />
```

Layout: a 2-column grid (`grid-cols-[320px_1fr]`). The **left column is the character preview with equipment slots overlaid on top**. The 3D doll fills the entire left pane and slot icons sit absolutely positioned over it. The right column is the bag grid plus weight bar. Equipment slots are rendered conditionally: `hasSlot('helmet')` checks the character's `equipmentSlots` array, so non-humanoid creatures show only the slots they support.

### Stat Pills

A row of pills along the top of the preview pane shows the live HP and armor pools:

| Pill | Icon | Condition |
|------|------|-----------|
| HP | `ph:heart-fill` (red) | always |
| Physical armor | `ph:shield-fill` (white) | `maxArmor.physical > 0` |
| Magical armor | `ph:shield-star-fill` (blue) | `maxArmor.magical > 0` |

Max values come from `gameStore.derivedMaxArmor(character.id)` (see [Combat &rarr; Armor](/combat/armor)).

### Slot Positioning

Slots are placed in four zones over the preview, each gated by `hasSlot(...)`:

- **Top center**: `helmet`.
- **Left column** (body, starting below the helmet): `armor`, `trousers`, `gauntlets`, `boots`.
- **Right column** (accessories, starting below the helmet): `cloak`, `amulet`, `ring1`, `ring2`.
- **Bottom center**: `mainHand`, `offHand`.

That is all 11 keys in `ALL_EQUIPMENT_SLOTS`. The layout decouples slot count from grid columns. Adding a new slot only needs one more `<InventoryEquipmentSlot>` in a column plus entries in `SLOT_LABELS` / `SLOT_ICONS`.

## CharacterPreview

A small `<TresCanvas>` showing the character with currently-equipped weapons attached to their bones, the **doll**. Equipment changes in the store reflect on the doll in real time.

```vue
<InventoryCharacterPreview :character-id="character.id" />
```

`CharacterPreview` owns the store lookups and picks the model component:

```ts
const entity = computed(() => gameStore.getEntity(props.characterId))
const equipment = computed(() => gameStore.derivedEquipment(props.characterId))

const isModular = computed(() => !!entity.value?.appearance)
const modelUrl = computed(() => entity.value?.model ?? null)
const rigKey = computed(() => entity.value?.rig ?? 'Rig_Medium')
```

- An entity with an `appearance` block is a modular character and renders through `ModularCharacterPreviewModel`.
- Otherwise the entity's `model` URL renders through `CharacterPreviewModel` inside `<Suspense>`.
- With neither `model` nor `appearance` the canvas is skipped and a "No model" placeholder shows.

The canvas uses `createTransparentWebGPURenderer` from the runtime so the modal background shows through. The camera is a `TresPerspectiveCamera` at `[2, 1.3, 8]` looking at `[0, 1.2, 0]` with `fov: 35`, a narrow, slightly-offset framing that keeps the body centered while leaving room for the overlaid equipment slots on either side. Adjust these values if you re-skin the modal at a different aspect ratio.

### CharacterPreviewModel

Props: `modelUrl: string`, `rigKey: string`, `equipment: Equipment`. It is an async component (awaits inside setup), so its parent must be a `<Suspense>` boundary.

1. `useGLTF(modelUrl, { draco: true })` and `await execute()`.
2. Resolves the rig by name: `nodes.value?.[rigKey]`. The rig is a named node inside the GLTF, not the scene root, because `useEquipment` resolves hand bones with `useGraph(rig)`.
3. `useEquipment(rig, toRef(props, 'equipment'))` and `useCharacterAnimations(rig, rigSize)`, where `rigSize` is `rigKey` with the `Rig_` prefix removed.

### ModularCharacterPreviewModel

Props: `characterId: string`. It builds its **own** rig instance from the entity's `appearance`:

```ts
const { rig } = useModularRig(() => entity.value?.appearance, useModularArmor(() => props.characterId))
useEquipment(rig, computed(() => gameStore.derivedEquipment(props.characterId)))
useCharacterAnimations(rig, 'Medium')
```

The world scene already renders a copy of this character, and a Three object cannot live in two scenes at once, so the preview never reuses the in-world rig. Armor pieces come from `useModularArmor`, which reads the character's equipped items, so the doll wears the same armor set as the world model.

The animation hook auto-plays the idle clip in both paths, so the doll breathes instead of T-posing.

::note
The doll uses the same `useEquipment` composable as the in-world character (see [Equipment](/characters/equipment)). There is no separate "preview" attach path.
::

## EquipmentSlot

One slot in the doll layout.

```vue
<InventoryEquipmentSlot
  slot-key="mainHand"
  :character-id="character.id"
  @context="onEquipmentContext"
/>
```

What it does:

- Reads the equipped item via `equippedAt(characterId, slotKey)`.
- Shows the item's `icon` (or a slot-default Lucide icon if empty).
- Acts as a drop zone: accepts dragged items, calls `moveItem` with the slot.
- Emits `context` on right-click so the parent can open the item menu.
- Visually pulses when a valid item is being dragged; flashes red for invalid types.

Slot label and default icon are looked up from local `SLOT_LABELS` and `SLOT_ICONS` maps. These are presentation-only and don't leak into the store.

## BagGrid

The 8 × 6 grid on the right side of the modal.

```vue
<InventoryBagGrid
  :character-id="character.id"
  @item-context="onItemContext"
/>
```

Behavior:

- Iterates `itemsIn(characterId)` (which skips equipped items).
- Fills the remaining cells with empty placeholders so the grid stays rectangular.
- Acts as a drop zone for **any** item not already loose in this bag, including unequipping by dropping into the same bag.
- Renders a `WeightBar` underneath.

The grid never paginates. If you add more rows than `ROWS_VISIBLE` (6), it scrolls internally.

## ItemCell

A single cell. Used in the bag, the loot popover, and anywhere else items need a 2D representation.

```vue
<InventoryItemCell
  :item="item"
  size="md"
  @click="..."
  @contextmenu="..."
/>
```

- Renders `item.icon` (or a cube fallback).
- Shows a small quantity badge in the bottom-right when `quantity > 1`.
- Is `draggable`: calls `useItemDrag().start(item)` on `dragstart`.
- Wraps in a `UTooltip` that renders `ItemTooltip` as the content.
- Accepts `item: null` to render an empty placeholder cell.

## ItemTooltip

The hover card that appears over items. Designed so the icon "pops out" of the top-right corner using absolute positioning and `drop-shadow`.

```vue
<InventoryItemTooltip :item="item" />
```

Shows name, subtype, and any of: damage dice, effect, weight, value, and a chip-style list of properties (`versatile`, `light`, etc.). Conditionally rendered: if the field isn't on the item, the row is omitted.

## WeightBar

```vue
<InventoryWeightBar :current="weight" :capacity="capacity" />
```

Three states based on the ratio:

| Ratio | Color | Meaning |
|-------|-------|---------|
| < 0.8 | gold | normal |
| 0.8 – 1.0 | warning | heavy |
| ≥ 1.0 | error | over capacity → encumbered |

The bar caps visually at 100% even though the underlying ratio can exceed 1.0.

## Putting It All Together

You do not mount anything yourself. `Hud` (from `@artificer-forge/engine/ui`) renders the three inventory singletons together with the rest of the 2D overlay, and `<Game>` renders `<Hud />` as the fallback of its `#hud` slot:

```vue
<!-- packages/engine/src/ui/components/Hud.vue -->
<EntityContextMenu :state="state" @update:open="state.open = $event" @action="emitAction" />
<ActionBar />
<CharacterInventoryModal />
<LootPopover />
<ItemContextMenu />
<DialogPanel />
```

```vue
<!-- packages/engine/src/Game.vue -->
<slot name="hud">
  <Hud />
</slot>
```

If you override `#hud` with your own overlay, add `CharacterInventoryModal`, `LootPopover` and `ItemContextMenu` back yourself, or the hotkey and the loot/context actions will change state that nothing renders.

Everything else (opening, focusing a character, drag-and-drop, context menus, hotkeys) is wired through the shared composables described in [Interactions](/inventory/interactions).
