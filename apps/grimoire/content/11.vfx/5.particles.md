`@artificer-forge/vfx` ships three particle factories for fire and ember effects. They cover two very different cost/control trade-offs:

| Factory | Backing | Animation | Use for |
|---------|---------|-----------|---------|
| `createEmberSystem` | `THREE.Points` | **CPU**, per-frame in your loop | A single character on fire |
| `createInstancedEmberSystem` | `InstancedMesh` | **GPU** (TSL vertex shader) | Sparks rising off a fire *surface* |
| `createFireBillboards` | `InstancedMesh` | **GPU** (TSL vertex shader) | Vertical flame billboards over the fire cells of a field |

::note
The two GPU systems read a fire `DataTexture` so particles only appear above active fire cells. Keep that texture updated (re-pack + `needsUpdate`) each frame. The surface system in `@artificer-forge/engine` owns it.
::

## createEmberSystem

A CPU-driven `THREE.Points` cloud of 60 embers that drift upward around a burning character. It returns the `Points` object plus the raw buffers and per-particle metadata, so **you** advance the simulation in your render loop.

```ts
import { createEmberSystem, RESET_Y } from '@artificer-forge/vfx'

const { points, geometry, positions, colors, meta } = createEmberSystem()
characterGroup.add(points)   // local to the character

function tick(delta: number) {
  for (let i = 0; i < meta.length; i++) {
    const m = meta[i]
    positions[i * 3 + 1] += m.speed * delta              // rise
    if (positions[i * 3 + 1] > RESET_Y) {
      positions[i * 3 + 1] = m.initialY                  // respawn at base
    }
    // optional: horizontal wobble from m.wobblePhase / m.wobbleFreq
  }
  geometry.attributes.position.needsUpdate = true
}
```

The returned bundle: `{ points, geometry, positions, colors, meta }`: `positions`/`colors` are the `Float32Array`s backing the geometry attributes; `meta` is an `EmberMeta[]`.

```ts
interface EmberMeta {
  angle: number        // spawn angle (radians)
  radius: number       // distance from character center (0.12–0.55)
  initialY: number     // reset Y on loop (0–0.2)
  speed: number        // upward drift (0.5–1.5)
  wobblePhase: number  // phase offset for horizontal wobble
  wobbleFreq: number   // wobble frequency (1.2–3.7)
}
```

### Constants and color helpers

| Export | Value | Description |
|--------|-------|-------------|
| `EMBER_COUNT` | `60` | Number of particles |
| `CHAR_HEIGHT` | `2.2` | Assumed character height (world units) |
| `MAX_RADIUS` | `0.55` | Max spawn radius from center |
| `RESET_Y` | `2.6` | Despawn height (`CHAR_HEIGHT + 0.4`) |

`heatColor(heat)` returns an `[r, g, b]` on a deep-red → orange → yellow ramp; `lerpRgb(...)` is the linear interpolation it builds on. `createEmberSystem` uses them internally to color each ember; export them if you want matching colors elsewhere.

```ts
import { heatColor } from '@artificer-forge/vfx'
const [r, g, b] = heatColor(0.75) // orange-yellow
```

## createInstancedEmberSystem

A GPU spark system: an `InstancedMesh` of tiny camera-agnostic quads whose entire lifecycle (rise, drift, fade) runs in a TSL vertex shader: **zero per-frame CPU work**. Each instance loops on its own random offset and is suppressed wherever the fire texture reads empty.

```ts
import { createInstancedEmberSystem } from '@artificer-forge/vfx'

// width / depth = the fire field's world extents, fireTex = packed fire DataTexture
const { mesh } = createInstancedEmberSystem(WIDTH, DEPTH, fireTex, 200)
```

```vue
<template>
  <primitive :object="mesh" />
</template>
```

| Param | Default | Description |
|-------|---------|-------------|
| `width` | required | Fire field width (world units) |
| `depth` | required | Fire field depth (world units) |
| `fireTex` | required | Packed fire `DataTexture` (R = coverage) |
| `count` | `200` | Number of ember instances |

Returns `{ mesh }`. Embers rise ~2.5m over their life, drift on sine/cosine paths, fade in fast and out before reset, and render as a soft white-hot-core → orange-rim circle (additive).

## createFireBillboards

Vertical flame billboards spread within `±spawnRadius` of the mesh origin. Like the instanced embers, the motion and flame shader run on the GPU, but each quad is **cylindrically camera-facing**, so flames stay upright and never go edge-on as the camera orbits. Each billboard samples the fire texture at its own XZ and hides itself where the cell holds no fire, so you never place billboards per pool.

This is how the engine's `SurfaceSystem` uses it: one field-wide cluster, mesh at the origin, radius half the field.

```ts
import { createFireBillboards } from '@artificer-forge/vfx'

// packages/engine/src/runtime/components/SurfaceSystem.vue (trimmed)
const { mesh } = createFireBillboards(
  width,
  depth,
  fireTex,
  Math.round(width * depth * billboardDensity), // count: per-m² density, default 5
  Math.max(width, depth) / 2,                   // spawnRadius: cover the whole field
  flipbook,
)
mesh.position.set(0, 0, 0)
mesh.renderOrder = 4 // after pool (0), charcoal (1), fire plane (2), embers (3)
```

```vue
<template>
  <primitive :object="mesh" />
</template>
```

| Param | Default | Description |
|-------|---------|-------------|
| `fieldWidth` | required | Fire field width (world units); maps billboard XZ to texture UV |
| `fieldDepth` | required | Fire field depth (world units) |
| `fireTex` | required | Packed fire `DataTexture` (R = coverage) |
| `count` | `60` | Number of billboard instances |
| `spawnRadius` | `1.5` | Billboards spread within ±radius of the mesh origin |
| `flipbookTex` | none | Optional 16×4 flame flipbook sprite (24 fps) |

Returns `{ mesh }`. Without `flipbookTex` it uses the same two-pass procedural flame shader as `buildFireSurfaceMaterial` (warp + body, 4-stop heat ramp, edge/height fades). Pass a `flipbookTex` to play an animated flame sprite instead. Luminance drives the additive opacity, so dark sprite backgrounds vanish and bright cores add their color regardless of the texture's alpha format.

::note
Keep the mesh at the field origin and let `spawnRadius` cover the field. The fire texture decides where flames show, so a painted fire anywhere on the grid gets billboards without any repositioning. The small default (`1.5`) only fits a standalone campfire-sized field. Hidden billboards still rasterize, so `count` is a fill-rate budget: the engine's default is `width * depth * 5`.
::

::warning
Because instance positions are computed in the vertex shader, the `InstancedMesh` bounding sphere sits at the mesh origin. Three's transparent sort therefore ties with any plane centred on the same spot. Pin `renderOrder` explicitly (see [Surface System](/surfaces/surface-system#what-it-builds)) instead of relying on the sort.
::
