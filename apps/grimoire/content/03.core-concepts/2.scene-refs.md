---
title: Scene Refs
description: The shared registry that lets stores and systems call imperative methods on rendered Character and Interactable components by entity id.
---

`useSceneRefs` is a globally shared composable that holds live references to rendered 3D components. It bridges the Pinia game store (which knows entity ids and stats) and the Vue component tree (which holds the Three.js objects and imperative methods).

```ts
import { useSceneRefs } from '@artificer-forge/engine/runtime'
```

## The problem it solves

The store tracks entity state (HP, position, status effects) but cannot call methods on a `Character` instance to play an animation or walk to a point. Combat, dialog, the camera follow and the playground command palette all need those imperative actions.

Scene refs provide a shared, singleton registry:

- `Character` and `Interactable` expose methods with `defineExpose`; the experience page registers them through a `:ref` callback.
- Stores and composables look the ref up by entity id and call it.

Because `useSceneRefs` is built with `createSharedComposable` from VueUse, every caller shares the same Maps. No prop drilling, no event bus.

## Interfaces

### `CharacterRef`

```ts
import type { AnimationAction, Object3D, Vector3 } from 'three'
import type { EventHookOn } from '@vueuse/core'
import type { AnimationNameType, PlayOptions } from '@artificer-forge/engine/runtime'

export interface CharacterRef {
  play: (name: AnimationNameType, fadeTimeOrOpts?: number | PlayOptions, timeScale?: number) => void
  actions: Readonly<Record<string, AnimationAction | null>>
  getPosition: () => Vector3 | null
  moveTo: (point: Vector3) => void
  onArrive: EventHookOn<Vector3>
  showDamage: (value: number, type: string, critical?: boolean) => void
  meleeAttack: () => void
  lookAt: (point: Vector3) => void
  attachToHand: (slot: 'mainHand' | 'offHand', object: Object3D) => void
  detachFromHand: (slot: 'mainHand' | 'offHand') => void
  cancelMovement: () => void
}
```

| Member | Purpose |
|--------|---------|
| `play(name, fadeTimeOrOpts?, timeScale?)` | Play a clip with optional cross-fade time or `{ fadeTime, timeScale, once }` |
| `actions` | The rig's `AnimationAction` map. Read-only; use it to check whether a clip exists (`actions[AnimationName.DEATH_A_POSE]`) |
| `getPosition()` | The group's **live** position. The store only syncs position on arrival, so trail, trample and camera-follow read this |
| `moveTo(point)` | Start walking toward a world-space point |
| `onArrive` | VueUse event hook. Returns `{ off }` to unsubscribe |
| `showDamage(value, type, critical?)` | Spawn a floating damage number. See [Damage Numbers](/characters/damage-numbers) |
| `meleeAttack()` | Plays `MELEE_1H_ATTACK_CHOP`. Hit resolution is the ability system's job |
| `lookAt(point)` | Instant yaw toward a point |
| `attachToHand(slot, object)` / `detachFromHand(slot)` | Parent an object to `handslotr` / `handslotl`. Replaces any previous attachment in that slot |
| `cancelMovement()` | Stop an in-progress move |

### `InteractableRef`

```ts
export interface InteractableRef {
  toggle: () => void
}
```

`toggle` opens or closes the interactable (chest lid, corpse) based on its current `opened` state.

## API

```ts
const {
  characterRefs,     // Ref<Map<string, CharacterRef>>
  interactableRefs,  // Ref<Map<string, InteractableRef>>
  setCharacterRef,
  getCharacterRef,
  setInteractableRef,
  getInteractableRef,
} = useSceneRefs()
```

| Symbol | Type | Purpose |
|--------|------|---------|
| `characterRefs` | `Ref<Map<string, CharacterRef>>` | All registered characters |
| `interactableRefs` | `Ref<Map<string, InteractableRef>>` | All registered interactables |
| `setCharacterRef(entityId, ref)` | `(string, CharacterRef \| null) => void` | Register, or unregister with `null` |
| `getCharacterRef(entityId)` | `(string) => CharacterRef \| null` | Look up by entity id |
| `setInteractableRef(entityId, ref)` | `(string, InteractableRef \| null) => void` | Register or unregister |
| `getInteractableRef(entityId)` | `(string) => InteractableRef \| null` | Look up by entity id |

## Usage pattern

### 1. Register, in the experience component

The experience renders inside `<Game>`'s default slot, so there is no `<TresCanvas>` or camera here. `:ref` with a callback registers on mount and, because Vue calls it with `null` on unmount, unregisters automatically.

```vue [experience.vue]
<script setup lang="ts">
import { Character, Floor, useGameStore, useSceneRefs } from '@artificer-forge/engine/runtime'

const gameStore = useGameStore()
const { setCharacterRef } = useSceneRefs()

const characterEntities = computed(() =>
  [...gameStore.entities.values()].filter(e => e.type === 'character'),
)
</script>

<template>
  <TresAmbientLight :intensity="0.8" />
  <Character
    v-for="entity in characterEntities"
    :ref="(el: any) => setCharacterRef(entity.id, el)"
    :key="entity.id"
    :entity-id="entity.id"
  />
  <Floor />
</template>
```

### 2. Expose, inside `Character`

The engine's `Character.vue` exposes more than `CharacterRef` requires. The extra members are handy from a `:ref` in a page but are not part of the typed contract:

```ts
defineExpose({
  play,
  stop,
  getPosition,
  currentAnimName,
  actions,
  AnimationName,
  moveTo,
  cancelMovement,
  onArrive,
  showDamage,
  meleeAttack,
  lookAt: lookAtPoint,
  attachToHand,
  detachFromHand,
})
```

`stop`, `currentAnimName` and the `AnimationName` enum are exposed but absent from `CharacterRef`. Cast if you need them from a typed ref.

### 3. Consume, from a store or composable

```ts
import { useSceneRefs } from '@artificer-forge/engine/runtime'

const { getCharacterRef } = useSceneRefs()

function walkAndHit(attackerId: string, targetId: string, point: Vector3) {
  const attacker = getCharacterRef(attackerId)
  const target = getCharacterRef(targetId)
  if (!attacker || !target) return

  // Subscribe once, then move. `off` removes the listener after the first arrival.
  const { off } = attacker.onArrive(() => {
    attacker.meleeAttack()
    target.showDamage(12, 'slashing')
    off()
  })
  attacker.moveTo(point)
}
```

### 4. Interactables

`Interactable` takes `entityId` and an optional `debug` flag (BVH visualisation). It emits `interact` with the entity id on left click and opens the context menu on right click. The chest page registers the ref and drives it after the character arrives:

```vue [pages/interactable/chest/experience.vue]
<script setup lang="ts">
import { Character, Interactable, useGameStore, useSceneRefs } from '@artificer-forge/engine/runtime'
import { Vector3 } from 'three'

const gameStore = useGameStore()
const { setCharacterRef, setInteractableRef, getCharacterRef, getInteractableRef } = useSceneRefs()

const INTERACTION_DISTANCE = 1.5

function handleInteractableClick(entityId: string) {
  const interactable = gameStore.getEntity(entityId)
  const player = gameStore.selectedEntity
  const playerRef = gameStore.selectedEntityId ? getCharacterRef(gameStore.selectedEntityId) : null
  if (!interactable || !player || !playerRef) return

  // Stop INTERACTION_DISTANCE short of the chest, on the player's side.
  const chestPos = new Vector3(interactable.position.x, interactable.position.y, interactable.position.z)
  const playerPos = new Vector3(player.position.x, player.position.y, player.position.z)
  const targetPos = chestPos.clone().add(playerPos.sub(chestPos).normalize().multiplyScalar(INTERACTION_DISTANCE))
  targetPos.y = 0

  const { off } = playerRef.onArrive(() => {
    getInteractableRef(entityId)?.toggle()
    off()
  })
  playerRef.moveTo(targetPos)
}
</script>

<template>
  <Character
    v-for="entity in gameStore.partyEntities"
    :ref="(el: any) => setCharacterRef(entity.id, el)"
    :key="entity.id"
    :entity-id="entity.id"
  />
  <Interactable
    v-for="entity in interactableEntities"
    :ref="(el: any) => setInteractableRef(entity.id, el)"
    :key="entity.id"
    :entity-id="entity.id"
    @interact="handleInteractableClick"
  />
</template>
```

The same handler serves the context menu's `use` and `close` actions. See [Entity Commands](/core-concepts/commands) and [Interactables](/entities/interactables).

::note
`useSceneRefs` uses `createSharedComposable`: every call returns the same Maps. There is no need to pass refs down through props or inject/provide.
::

::warning
Refs exist only after the component has mounted and the `:ref` callback has fired. Always guard: `getCharacterRef(id)?.play(...)`.
::
