The game store is the single source of truth for runtime state: entities, party, inventory, world flags, selection and input blocking. It is a Pinia composition-API store shipped from the engine's runtime layer.

```ts
import { useGameStore } from '@artificer-forge/engine/runtime'

const gameStore = useGameStore()
```

## State

| Property | Type | Default | Purpose |
|----------|------|---------|---------|
| `currentScene` | `Ref<string>` | `'main'` | Id of the last loaded scene |
| `worldFlags` | `Ref<Record<string, boolean \| number>>` | `{}` | Quest progress and world state |
| `entities` | `Ref<Map<string, EntityState>>` | empty | Every character, item and interactable |
| `party` | `{ members: string[], leader: string \| null }` | empty | Player-controlled characters |
| `selectedEntityId` | `Ref<string \| null>` | `null` | The focused entity (targeting, action bar, HUD) |
| `inputBlocked` | `Ref<boolean>` | `false` | Set by modal and dialog systems to suspend world input (click-to-move, OrbitControls) |

Inventory is **not** a separate domain. Items are first-class entities in `entities`, tagged with `containerId` and `slot`. See [Inventory Overview](/inventory/overview).

## Content source

The engine never fetches content. The app injects a `ContentSource` once, and every spawn or scene load goes through it. Without it the store throws `[game] content source not configured — call useGameStore().configureContent() at app init`.

```ts
export interface ContentSource {
  resolveTemplate: (templateId: string) => Promise<EntityTemplate | null>
  resolveScene: (sceneId: string) => Promise<SceneDef | null>
  resolveAbility: (abilityId: string) => Promise<any | null>
  resolveDialog: (dialogId: string) => Promise<any | null>
  resolveClass: (classId: string) => Promise<ClassTemplate | null>
}
```

| Resolver | Consumer | Content collection in the playground |
|----------|----------|--------------------------------------|
| `resolveTemplate` | `spawnFromTemplate`, `spawnItemEntity`, `loadScene` | `entities` (by `templateId`) |
| `resolveScene` | `loadScene` | `scenes` (by `sceneId`) |
| `resolveAbility` | ability system | `abilities` (by `abilityId`) |
| `resolveDialog` | dialog engine | `dialogs` (by `dialogId`) |
| `resolveClass` | action bar emblem and accent colour | `classes` (by `classId`) |

`configureContent(source)` stores it. The store also exposes `resolveTemplate`, `resolveAbility`, `resolveDialog` and `resolveClass` as public gateways for other engine systems. `resolveScene` has no public gateway; only `loadScene` uses it.

The playground wires Nuxt Content in a plugin so the source exists before any page mounts. See [Installation: content source](/getting-started/installation#content-source-gamedatats).

::warning
Call `configureContent()` before the first `spawnFromTemplate` or `loadScene`. A Nuxt plugin is the right place. A page `onMounted` is too late if another page spawned first.
::

`EntityTemplate` is loosely typed (`{ templateId, type, [key: string]: any }`); the app guarantees the shape through its content schema. See [Entity Templates](/entities/templates).

## Entity State

The full `EntityState` from `stores/game.ts`. Most fields are optional because one interface covers characters, items and interactables.

```ts
export interface EntityState {
  id: string
  templateId: string
  type: 'character' | 'item' | 'interactable'
  subtype?: string          // 'npc', 'corpse', 'container', 'weapon', 'armor', ...
  name: string
  position: Position
  rotation?: Position
  moveTarget?: Position | null

  // Rendering
  portrait?: string
  portraitBackground?: string
  icon?: string
  model?: string
  rig?: string
  animations?: Record<string, unknown>

  // Character
  class?: string
  level?: number
  race?: string
  sex?: Sex
  appearance?: CharacterAppearance   // presence switches rendering to modular assembly
  faction?: string
  team?: Team                        // 'player' | 'ally' | 'neutral' | 'hostile'
  controllable?: boolean
  recruitable?: boolean
  hp?: number
  maxHp?: number
  physicalArmor?: number             // current pools; max is derived from equipment
  magicalArmor?: number
  stats?: Record<string, number>
  ai?: { behavior: string, [key: string]: unknown }
  dead?: boolean
  statusEffects?: StatusEffect[]     // { id: StatusEffectId, turnsLeft?: number }
  abilities?: string[]
  dialogId?: string

  // Interactable
  locked?: boolean
  opened?: boolean
  destructible?: boolean

  // Container (characters, chests, corpses)
  container?: ContainerInfo          // { capacity?: number }, currently unread
  equipmentSlots?: EquipmentSlotKey[]

  // Item instance (type === 'item')
  containerId?: string | null        // owning entity id, or null = in world
  slot?: EquipmentSlotKey            // when equipped
  quantity?: number
  stackable?: boolean
  maxStack?: number
  weight?: number                    // per unit (kg)

  // Item template metadata copied at spawn
  modular?: { slot: ModularSlot, hides: string[], assets?: Partial<Record<Sex | 'any', string>>, rig?: 'medium' | 'small' }
  texture?: { base: string, tints?: { id: string, label: string, map: string }[] }
  damage?: { dice: string, type: string }
  armor?: { physical?: number, magical?: number }
  properties?: string[]
  range?: { normal: number, long: number }
  effect?: { type: string, dice?: string, bonus?: number }
  value?: number
  usable?: boolean
}
```

`EquipmentSlotKey` has 11 values, listed in `ALL_EQUIPMENT_SLOTS`: `helmet, amulet, armor, cloak, trousers, gauntlets, boots, ring1, ring2, mainHand, offHand`.

## Entity actions

| Action | Signature | Notes |
|--------|-----------|-------|
| `spawnEntity` | `(id, state: EntityState) => void` | Raw insert |
| `updateEntity` | `(id, partial: Partial<EntityState>) => void` | Shallow merge; replaces the Map entry so watchers fire |
| `removeEntity` | `(id) => void` | Also removes the id from `party.members` |
| `getEntity` | `(id) => EntityState \| undefined` | |
| `spawnFromTemplate` | `(templateId, position, overrides?) => Promise<string>` | Throws if the template is missing. Returns the instance id |
| `spawnItemEntity` | `(templateId, opts) => Promise<string \| null>` | Returns `null` (with a `console.warn`) if the template is missing or not an item |

### `spawnFromTemplate`

Instance id is `${templateId}_${Date.now()}`. The store copies these template fields onto the entity: `subtype, name, portrait, portraitBackground, model, rig, animations, class, level, race, sex, appearance, faction, team (default 'neutral'), controllable, recruitable, hp, maxHp, stats, ai, locked, destructible, equipmentSlots, dialogId`. `hp`/`maxHp` prefer `template.stats.hp` over top-level `template.hp`. Then:

1. `abilities` = `['melee-attack', 'dash', 'throw']` (the `DEFAULT_ABILITIES`) followed by `template.abilities`.
2. `statusEffects` = `[]`.
3. `overrides` are spread last, so they win over everything above.
4. For **characters** with `template.equipment`, each of the 11 `ALL_EQUIPMENT_SLOTS` that names an item template is spawned with `spawnItemEntity(itemId, { containerId, slot })`, then `refreshArmor(instanceId)` fills the armor pools.
5. For **interactables** with `template.lootTable`, each entry is rolled against `entry.chance`; `quantity` may be a number or a `[min, max]` range. Winners are spawned into the container.

```ts
const playerId = await gameStore.spawnFromTemplate('cedric', { x: 0, y: 0, z: 0 })
// cedric.yaml lists mainHand, armor, cloak, trousers, gauntlets, boots:
// six item entities now exist with containerId = playerId and a slot each.
```

### `spawnItemEntity`

```ts
spawnItemEntity(templateId: string, opts: {
  containerId?: string | null   // default null (in world)
  slot?: EquipmentSlotKey
  position?: Position           // default { x: 0, y: 0, z: 0 }
  quantity?: number             // default 1
}): Promise<string | null>
```

Copies `subtype, name, icon, model, stackable (false), maxStack (1), weight (0), modular, texture, damage, armor, properties, range, effect, value, usable` from the item template. Instance ids get a random suffix so two stacks spawned in the same millisecond do not collide.

## Scene actions

### `loadScene`

Loads a scene through `resolveScene`, clears world entities (keeps party members and the items they own), spawns the scene's entities, and returns the requested spawn point (falls back to `default`).

```ts
async function loadScene(sceneId: string, spawnPointId: string = 'default') {
  const scene = await requireContent().resolveScene(sceneId)
  if (!scene) throw new Error(`Scene not found: ${sceneId}`)

  for (const [id, entity] of entities.value) {
    if (party.members.includes(id)) continue
    if (entity.type === 'item' && entity.containerId && party.members.includes(entity.containerId)) continue
    entities.value.delete(id)
  }

  currentScene.value = sceneId

  for (const entry of scene.entities) {
    await spawnFromTemplate(entry.templateId, entry.position, { rotation: entry.rotation, ...entry.overrides })
  }

  const spawnPoint = scene.spawnPoints[spawnPointId] ?? scene.spawnPoints.default
  return { scene, spawnPoint }
}
```

```ts
const { spawnPoint } = await gameStore.loadScene('interactable_scene')
gameStore.updateEntity(playerId, { position: spawnPoint })
```

See [Scenes](/entities/scenes) for the YAML format.

## Party actions

| Action | Signature | Notes |
|--------|-----------|-------|
| `addToParty` | `(entityId) => void` | First member becomes `leader` |
| `removeFromParty` | `(entityId) => void` | Leader falls back to `members[0]` or `null` |
| `setPartyLeader` | `(entityId) => void` | No-op for non-members |
| `recruitEntity` | `(entityId) => void` | Requires `recruitable: true` and not already a member. Sets `team: 'player'`, `controllable: true`, `ai: { behavior: 'companion' }`, clears `subtype`, then `addToParty` |
| `dismissEntity` | `(entityId) => void` | Requires `recruitable` and membership. `removeFromParty`, then `team: 'neutral'`, `controllable: false`, `ai: { behavior: 'idle' }`, `subtype: 'npc'` |

`zynrae` is the playground's recruitable NPC (`team: neutral, recruitable: true`). See [Companions](/actors/companions).

## Selection

```ts
function selectEntity(entityId: string | null) {
  selectedEntityId.value = entityId
  if (entityId) setPartyLeader(entityId)
}
```

Selecting a party member also makes them the leader, because the action bar and the ability system are keyed off `party.leader`. `setPartyLeader` no-ops for non-party ids, so selecting an enemy does not change the leader.

## Combat and armor

```ts
applyDamage(targetId: string, amount: number, damageTypeId: string): { armorAbsorbed: number, hpDamage: number }
```

Looks up the damage type's `armorType` in `useDamageTypeStore`, calls `computeDamage` from `/core` (depletes the matching armor pool first, overflow hits HP), writes the result with `updateEntity`, and returns the split. Unknown target returns `{ armorAbsorbed: 0, hpDamage: 0 }`.

| Action | Signature | Notes |
|--------|-----------|-------|
| `derivedMaxArmor` | `(entityId) => { physical, magical }` | Sum of `armor` on every equipped item (`containerId === entityId && slot`) |
| `refreshArmor` | `(entityId) => void` | Refills `physicalArmor`/`magicalArmor` to the derived max. Called on spawn and on every equip or unequip. No passive regen |

See [Armor](/combat/armor).

## Inventory actions

Every inventory move routes through one primitive, `moveItem`. It validates, merges stacks, splits partial quantities, reparents, then syncs encumbrance and armor.

```ts
moveItem(itemId: string, target: {
  containerId: string | null    // null = drop into the world (position required)
  slot?: EquipmentSlotKey
  position?: Position
  quantity?: number             // partial move splits a new stack
}): MoveResult

type MoveResult = { ok: true } | { ok: false, reason: MoveFailReason }
type MoveFailReason = 'no-slot' | 'wrong-type' | 'over-capacity' | 'occupied' | 'not-found' | 'invalid-target'
```

| Reason | When |
|--------|------|
| `not-found` | Item or target container does not exist, or the id is not an item |
| `invalid-target` | Drop without `position`, or a slot move with no container |
| `no-slot` | Target's `equipmentSlots` does not include the slot |
| `wrong-type` | `isItemTypeForSlot` rejects the item's `subtype` for that slot |
| `occupied`, `over-capacity` | Declared in the union but **never returned**. An occupied slot swaps (the occupant is unequipped); `container.capacity` is not read |

Convenience wrappers:

```ts
gameStore.pickupItem(itemId, characterId)   // world → bag
gameStore.dropItem(itemId, position)        // bag → world
gameStore.transferItem(itemId, toCharacter) // bag → bag
gameStore.equipItem(itemId, 'mainHand')     // bag → slot (item must already be in a container)
gameStore.unequipItem(itemId)               // slot → bag
```

`syncEncumbrance(characterId)` runs after every move on both the source and target containers. It adds `encumbered` when `encumbranceOf >= 1` and removes it below. `isItemTypeForSlot(item, slot)` is also exported for UI drop validation.

See [Inventory: Store API](/inventory/store-api) for the merge and split rules in detail.

## Full usage example

```ts
import { useGameStore } from '@artificer-forge/engine/runtime'

const gameStore = useGameStore()

// Party leader (persists across scenes)
const playerId = await gameStore.spawnFromTemplate('cedric', { x: 0, y: 0, z: 0 })
gameStore.addToParty(playerId)
gameStore.selectEntity(playerId)

// Scene: spawns its entities, returns the spawn point
const { spawnPoint } = await gameStore.loadScene('interactable_scene')
gameStore.updateEntity(playerId, { position: spawnPoint })

// Recruit the NPC standing nearby
const zynraeId = await gameStore.spawnFromTemplate('zynrae', { x: spawnPoint.x + 2, y: 0, z: spawnPoint.z })
gameStore.recruitEntity(zynraeId)

// Typed damage: armor pool first, overflow to HP
const { armorAbsorbed, hpDamage } = gameStore.applyDamage(targetId, 5, 'slashing')

// Loot: a stack of two potions straight into the bag
await gameStore.spawnItemEntity('healing_potion', { containerId: playerId, quantity: 2 })

// Progress
gameStore.setFlag('first_combat_complete', true)
```
