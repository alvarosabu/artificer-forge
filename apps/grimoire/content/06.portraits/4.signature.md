---
title: Signature
description: How a portrait's cache key is derived from a character's appearance, modular recipe, armor, equipment and backdrop, and exactly when it invalidates and forces a re-bake.
---

A portrait's cache key is its **signature**: a stable string built from everything that affects how the portrait *looks*, and nothing that does not. Same appearance produces the same signature, which is a cache hit; changed gear, tint or model produces a new signature, which forces a re-bake.

```ts
import { portraitSignature } from '@artificer-forge/engine/runtime'
```

## What goes into the signature

```ts
interface PortraitAppearance {
  model?: string
  appearance?: CharacterAppearance // modular recipe, instead of (or alongside) a model URL
  armor?: ArmorPiece[]             // resolved modular armor pieces
  rig?: string
  equipment: Equipment
  background?: string              // backdrop URL; part of the look
}

portraitSignature({ model, appearance, armor, rig, equipment, background })
// -> "v9|/models/characters/zynrae.glb|||Rig_Medium|dagger|dagger|/img/portraits/bgs/dark-forest.png"
```

The signature joins these parts with `|`, in this order:

| Part | Source | Why it matters |
|------|--------|----------------|
| `PORTRAIT_CACHE_VERSION` | constant (`v9`) | Pipeline version. Bump to invalidate everything |
| `model` | entity model URL, or empty | Different model = different face |
| `appearance` | `JSON.stringify(appearance)`, or empty | Modular recipe: body, head, hair, colours, tints, segment materials |
| `armor` | `id:tint` per piece, comma-joined, or empty | A jerkin or a crimson recolour changes the bust |
| `rig` | entity rig name | Different rig = different proportions |
| `equipment.mainHand` | derived equipment | A visible weapon changes the portrait |
| `equipment.offHand` | derived equipment | A visible off-hand item changes the portrait |
| `background` | resolved backdrop | The backdrop is part of the rendered frame |

::note
Only **`mainHand`** and **`offHand`** equipment feed the signature directly. For single-GLB characters, worn armor does not re-bake the portrait (it is not rendered on the model). For modular characters the `armor` part covers equipped helmet, armor, cloak, trousers, gauntlets and boots, because those pieces are meshes on the body.
::

## Why a signature instead of watching the entity

The game store replaces the **whole entity object** on every mutation, including each movement tick, HP change, and status update. Watching the entity directly would re-bake the portrait on every step the character takes.

`usePortraitRenderer` instead computes the signature and keys its watcher on that primitive string. Moving the character yields the same signature, so the watcher never fires and no bake runs. Only a real appearance change produces a new string.

The signature is also the **cache key** in the [portraits store](/portraits/bake-queue) and the **dedupe key** in the bake queue. There is no entity id in it: ids are minted per spawn, and two characters with the same look sharing one bake is the intended outcome.

## When it invalidates

A portrait re-bakes whenever the signature string changes, that is, whenever any of:

- the character's **model** changes,
- any field of a modular **appearance** changes (part id, `skinColor`, `hairColor`, horn settings, `equipmentTint`, `segmentMaterials`),
- an equipped modular **armor** piece is added, removed or swapped, or its **tint** changes,
- the **rig** changes,
- the **main-hand** or **off-hand** item changes (equip, unequip, swap),
- the **backdrop** changes (authored `portraitBackground` added, changed or removed),
- the **cache version** `PORTRAIT_CACHE_VERSION` is bumped.

Position, rotation, HP, armor pools, status effects and party membership do not touch the signature.

## The cache version

`PORTRAIT_CACHE_VERSION` (currently `'v9'`) is the first segment of every signature. Bump it whenever the render pipeline itself changes: framing in `PORTRAIT_CAMERA`, lighting in `PORTRAIT_LIGHTS`, tone mapping or exposure in `PORTRAIT_RENDERING`, capture resolution. Portraits baked by older logic then miss the cache and re-bake instead of being served stale.

::warning
The persistent cache is **on** (`PORTRAIT_CACHE_ENABLED = true` in `usePortraitRenderer.ts`). A framing or lighting change without a version bump ships stale portraits to anyone who already has `af:portraits` in `localStorage`.
::
