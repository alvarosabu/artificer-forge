Bloom adds glow around bright pixels. In this package it is three's `BloomNode` (`three/addons/tsl/display/BloomNode.js`) wrapped in `ScaledBloomNode`, which adds one thing three does not offer: a resolution scale for the mip chain.

The pass is added when `EffectComposer` receives a `bloom` prop. It reads the **unblurred** scene colour, even when DoF is on, so its threshold sees the true highlights and the glow is not smeared by the depth blur. The result is added on top of the scene (`outputNode.add(bloomPass)`).

## BloomConfig

Composer defaults apply when a field is missing from the prop. `GameConfig` defaults are what `<Game>` passes in practice (`defaultGameConfig()` in `packages/engine/src/runtime/useGameConfig.ts`).

| Name | Type | Composer default | GameConfig default | Purpose |
|------|------|------------------|--------------------|---------|
| `strength` | `number` | `0.5` | `0.7` | Multiplier on the blurred highlights before they are added back. |
| `radius` | `number` | `0` | `0.4` | Spread of the blur across the mip levels. |
| `threshold` | `number` | `0` | `0.8` | Luminance below which a pixel contributes nothing. |
| `smoothWidth` | `number` | `0.01` | `0.3` | Soft band above `threshold` where the contribution ramps from 0 to 1. |
| `resolutionScale` | `number` | `0.5` | `0.5` | Scale applied to the size three hands `setSize()`. `1` is three's stock chain (which already starts at half resolution), `0.5` is a quarter-resolution chain. |

The `bloom` prop is watched **deeply**. Changing a field writes into the node's uniforms (`strength`, `radius`, `threshold`, `smoothWidth`) or into `resolutionScale`. No rebuild happens. A `resolutionScale` change is picked up on the next frame because `BloomNode` calls `setSize` from `updateBefore` every frame.

## ScaledBloomNode

`packages/post-processing/src/ScaledBloomNode.ts`:

```ts
export class ScaledBloomNode extends BloomNode {
  resolutionScale: number

  setSize(width: number, height: number): void {
    super.setSize(
      Math.max(1, Math.round(width * this.resolutionScale)),
      Math.max(1, Math.round(height * this.resolutionScale)),
    )
  }
}
```

Why a subclass: three's `BloomNode` has no resolution option and re-reads the drawing-buffer size every frame. `setSize` is the only hook, so the incoming size is scaled there. The `Math.max(1, ...)` guard keeps a tiny canvas from asking for a 0-pixel target.

`scaledBloom(node, strength?, radius?, threshold?, resolutionScale?)` is the factory the composer calls. It wraps `node` in `nodeObject()` first, as three's own `bloom()` helper does.

::tip
Bloom is one of the passes that pays for the canvas `dpr`. `<Game>` clamps `dpr` to `[1, 1.5]`, and the default `resolutionScale: 0.5` halves the chain again. Raise the scale only if soft glow edges start to look blocky on large highlights.
::

## Tuning in the playground

`apps/playground/components/GameContextProvider.vue` binds a Leches panel to the reactive config. The folder is `postprocessing`, so the destructured keys are `postprocessingBloom*`:

```ts
const { postprocessingBloomStrength, postprocessingBloomThreshold, postprocessingBloomRadius, postprocessingBloomSmoothWidth, postprocessingBloomResolutionScale } = useControls('postprocessing', {
  bloomStrength: { value: config.bloom.strength, min: 0, max: 3, step: 0.01, type: 'range' },
  bloomRadius: { value: config.bloom.radius, min: 0, max: 1, step: 0.01, type: 'range' },
  bloomThreshold: { value: config.bloom.threshold, min: 0, max: 1, step: 0.01, type: 'range' },
  bloomSmoothWidth: { value: config.bloom.smoothWidth, min: 0, max: 1, step: 0.01, type: 'range' },
  bloomResolutionScale: { value: config.bloom.resolutionScale, min: 0.1, max: 1, step: 0.05, type: 'range' },
}, { uuid })

watchEffect(() => {
  config.bloom.strength = toValue(postprocessingBloomStrength)
  config.bloom.radius = toValue(postprocessingBloomRadius)
  config.bloom.threshold = toValue(postprocessingBloomThreshold)
  config.bloom.smoothWidth = toValue(postprocessingBloomSmoothWidth)
  config.bloom.resolutionScale = toValue(postprocessingBloomResolutionScale)
})
```

Because `<Game>` builds the `bloom` prop object from `config.bloom` in its template, every slider write reaches the composer's deep watcher on the same tick. See [Game Config](/engine-architecture/game-config) for how the config is provided.
