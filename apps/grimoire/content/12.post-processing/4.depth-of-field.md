Depth of field blurs fragments whose depth is far from a focus plane. In this package it is three's `DepthOfFieldNode` wrapped in `ScaledDepthOfFieldNode`, plus a small provide/inject API that lets a scene object claim the focus so the plane follows it.

The pass is added when `EffectComposer` receives a `dof` prop. It runs on the raw scene colour, before bloom and before the (disabled) outlines, because a blur after those would smear glow and edges across depth boundaries.

## Off by default

`defaultGameConfig()` ships `dof.enabled: false`. A top-down tactical camera puts the whole play area near one depth, so DoF reads as a tilt-shift miniature effect instead of a cinematic one. Turn it on per scene, or with the playground `dof` panel.

## DofConfig

| Name | Type | Composer default | GameConfig default | Purpose |
|------|------|------------------|--------------------|---------|
| `focalLength` | `number` | `4` | `6` | Depth band (world units) around the focus plane before a fragment is fully blurred. |
| `bokehScale` | `number` | `2` | `2` | Blur radius multiplier. `0` gives no visible blur, but the pass still runs. |
| `focusDistance` | `number` | `10` | `15` | Focus depth along the camera look direction. Used only when no focus target is registered. |
| `focusHeight` | `number` | `1` | `1` | Added to the focus target's world Y. A character group's origin is at the feet, so `1` puts the plane at the torso. |
| `smoothing` | `number` | `8` | `8` | Exponential smoothing rate for the tracked depth. Higher is snappier. |
| `resolutionScale` | `number` | `0.25` | `0.25` | Scale of the CoC and bokeh render targets. `0.5` is about three's stock chain, `0.25` is quarter resolution. |

`GameConfig.dof` has one extra field, `enabled: boolean`, which the composer never sees. `<Game>` maps it to the prop: `:dof="config.dof.enabled ? config.dof : undefined"`. Toggling it rebuilds the pipeline (see [EffectComposer](/post-processing/effect-composer#build-and-rebuild-rules)). Changing any other field writes into uniforms without a rebuild.

## Focus target API

`packages/post-processing/src/useDofFocus.ts`:

```ts
export interface DofFocusApi {
  /** null = the pass falls back to its fixed focusDistance. */
  target: ShallowRef<Object3D | null>
  setFocusTarget: (object: Object3D | null) => void
  /** Clears the target only if it is still `object`. */
  clearFocusTarget: (object: Object3D) => void
}
```

| Function | Returns | Notes |
|----------|---------|-------|
| `useDofFocusProvider()` | `DofFocusApi` | Creates the `target` ref and `provide`s it under `DofFocusKey`. `<Game>` calls it once. |
| `useDofFocus()` | `DofFocusApi \| null` | `inject(DofFocusKey, null)`. Returns `null` when no provider exists, so components work in scenes without post-processing. Always guard the result. |
| `setFocusTarget(object)` | `void` | Replaces the target. Pass `null` to fall back to `focusDistance`. |
| `clearFocusTarget(object)` | `void` | Clears only if `target === object`. This stale-unmount guard means a component that unmounts late cannot drop a newer target set by another component. |

### Consumer: the party leader

`Character.vue` claims the focus for the party leader, because the leader is what the camera follows:

```ts
const dofFocus = useDofFocus()

let focusedGroup: Group | null = null
watch([isLeader, characterRef], ([leader, group]) => {
  if (!dofFocus) return
  if (leader && group) {
    dofFocus.setFocusTarget(group)
    focusedGroup = group
  }
  else if (focusedGroup) {
    dofFocus.clearFocusTarget(focusedGroup)
    focusedGroup = null
  }
}, { immediate: true })
onUnmounted(() => {
  if (dofFocus && focusedGroup) dofFocus.clearFocusTarget(focusedGroup)
})
```

The pattern to copy: remember which object you registered, clear that exact object, and check for `null` before every call.

## Focus math

The composer updates the focus uniform every frame in an `onBeforeRender` callback (`EffectComposer.vue`):

```ts
onBeforeRender(({ delta, camera: active }) => {
  if (!props.dof) return
  const cam = toValue(active)
  const target = dofFocus?.target.value
  let wanted = props.dof.focusDistance ?? 10
  if (cam && target) {
    target.getWorldPosition(targetWorld)
    targetWorld.y += props.dof.focusHeight ?? 1
    cam.getWorldPosition(camWorld)
    cam.getWorldDirection(camForward)
    wanted = targetWorld.sub(camWorld).dot(camForward)
  }
  const rate = props.dof.smoothing ?? 8
  dofFocusDistance.value += (wanted - dofFocusDistance.value) * (1 - Math.exp(-rate * delta))
})
```

Two choices here are not obvious:

- **Dot with the camera forward, not `distanceTo()`.** `DepthOfFieldNode` compares against `-viewZ`, which is the distance along the camera axis. A euclidean distance grows toward the screen edges, so the focus would drift off a target that is not centred.
- **Exponential smoothing** `1 - exp(-rate * delta)` is frame-rate independent. `smoothing: 8` settles in roughly half a second; the camera follow uses the same shape.

::note
`useLoop`'s `camera` is a ref-like value. The callback wraps it in `toValue()` before calling `getWorldPosition`.
::

## ScaledDepthOfFieldNode

Three's `DepthOfFieldNode` (r183) has no resolution option. `packages/post-processing/src/ScaledDepthOfFieldNode.ts` overrides `setSize` and resizes the private render targets by hand:

| Target | Size | Why |
|--------|------|-----|
| `_invSize` | full resolution | Keeps the bokeh radius in full-res pixels, so the blur size on screen does not change with the scale. |
| `_compositeRT` | full resolution | The composite reads the sharp beauty pass back. Scaling it would blur the in-focus region too. |
| `_CoCRT`, `_CoCBlurredRT` | `width * scale` | Circle-of-confusion map and its blur. |
| `_blur64RT`, `_blur16NearRT`, `_blur16FarRT` | `width * scale` | The bokeh blur chain. |

The constructor checks that every field in `PRIVATE_FIELDS` exists on the instance and throws otherwise. This is why the package pins `three` to `^0.183.0`: a three release that renames one field fails loudly at build time, not with a silent black output.

`scaledDof(node, viewZNode, focusDistance, focalLength, bokehScale, resolutionScale?)` is the factory. The composer passes `scenePass.getViewZNode()` for depth and three `uniform()` nodes for the focus values, so they update without a rebuild.

## Tuning in the playground

`GameContextProvider.vue` exposes a `dof` Leches folder (`dofEnabled`, `dofFocalLength`, `dofBokehScale`, `dofFocusDistance`, `dofFocusHeight`, `dofSmoothing`, `dofResolutionScale`) and writes each value into `config.dof` in a `watchEffect`. Flipping `enabled` rebuilds the pipeline; the other sliders update live.
