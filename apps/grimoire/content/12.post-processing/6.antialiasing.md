---
title: Antialiasing
description: The three AntialiasMode values of the EffectComposer, what each costs, and why the mode is fixed at the first build.
---

```ts
export type AntialiasMode = 'msaa' | 'fxaa' | 'none'
```

`EffectComposer` takes it as the `antialias` prop (default `'msaa'`). `<Game>` passes `config.antialias`, and `defaultGameConfig()` also sets `'msaa'`. The engine declares the same union in `useGameConfig.ts` with a comment that it must match the composer's type.

## Modes

| Mode | Scene pass | Extra pass | Notes |
|------|------------|------------|-------|
| `'msaa'` | `pass(scene, camera)` with no explicit `samples`, so it inherits the renderer's 4x MSAA (`createWebGPURenderer` sets `antialias: true`) on a HalfFloat target. | none | Best edge quality. Any depth consumer (DoF, the water's `viewportDepthTexture`) then forces a full-resolution multisampled depth resolve on top. |
| `'fxaa'` | `pass(scene, camera, { samples: 1 })` | `fxaa(outputNode)` from `three/addons/tsl/display/FXAANode.js` | Cheapest with DoF on, because there is no multisampled depth to resolve. Softer on thin geometry (foliage, fences). |
| `'none'` | `pass(scene, camera, { samples: 1 })` | none | For measurement, or when the canvas is downscaled anyway. |

## FXAA moves tone mapping into the graph

FXAA thresholds on perceived luma, so it must see tone-mapped colour. When `antialias === 'fxaa'` (or when the renderer has a tone mapping other than `NoToneMapping`) the composer sets `renderPipeline.outputColorTransform = false` and appends `renderOutput(outputNode, renderer.toneMapping)` itself, then `fxaa()` after it:

```ts
if (rendererToneMapping !== NoToneMapping || useFxaa) {
  renderPipeline.outputColorTransform = false
  outputNode = renderOutput(outputNode, rendererToneMapping)
}
if (useFxaa) outputNode = fxaa(outputNode)
```

`<Game>` sets `:tone-mapping="NoToneMapping"`, so in `'msaa'` and `'none'` mode the pipeline's default output transform runs instead.

## Fixed at first build

Changing `antialias` after the pipeline exists does nothing except a warning:

```
[EffectComposer] antialias changed to "fxaa" after the pipeline was built; reload to apply.
```

The reason is outside the composer. Depth readers such as `viewportDepthTexture` cache a depth copy at the first pass's sample count. A rebuild with another count leaves them reading a texture of the wrong format and they render black. Set the mode in `provideGameConfig({ antialias: ... })` before `<Game>` mounts, and reload to switch.

::tip
If you want to A/B the modes for performance, do it on the same page with a reload between runs. Cross-run frame times on macOS are noisy; only interleaved toggles on one page are trustworthy.
::
