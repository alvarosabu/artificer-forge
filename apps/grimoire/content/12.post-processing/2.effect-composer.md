title: EffectComposer
description: The EffectComposer component, its four props, when the pass graph is rebuilt, and how to mount it outside <Game>.

`EffectComposer` is a renderless Tres component. Mount it once inside `<TresCanvas>`. It builds a `three/webgpu` `RenderPipeline` from the active scene and camera, then calls `renderer.replaceRenderFunction()` so every frame renders through the pipeline instead of the plain renderer.

Source: `packages/post-processing/src/EffectComposer.vue`.

## Props

All four props are optional.

| Name | Type | Default | Purpose |
|------|------|---------|---------|
| `outlinePresets` | `Record<string, OutlinePreset>` | `{ default: {} }` | One outline pass per key. Currently inert, see [Outline](/post-processing/outline). |
| `bloom` | `BloomConfig` | `undefined` (no bloom) | Adds the bloom pass. Watched deeply, see [Bloom](/post-processing/bloom). |
| `dof` | `DofConfig` | `undefined` (no DoF) | Adds the depth-of-field pass. Watched deeply, see [Depth of field](/post-processing/depth-of-field). |
| `antialias` | `AntialiasMode` | `'msaa'` | Sample count of the scene pass and whether FXAA runs at the end, see [Antialiasing](/post-processing/antialiasing). |

### The `dof: undefined` contract

`undefined` means "leave the DoF pass out of the graph". There is no `enabled` flag on the composer side. The engine keeps `enabled` in its own `GameConfig.dof` and translates it at the call site:

```vue
<EffectComposer :dof="config.dof.enabled ? config.dof : undefined" />
```

Passing `{ bokehScale: 0 }` is not the same: the pass still runs and still costs its render targets, it only produces no visible blur.

## Build and rebuild rules

The pass graph is compiled once. A watcher on `[scene, camera.activeCamera, () => !!props.dof]` decides when to build:

| Change | Effect |
|--------|--------|
| First scene + camera available | Build (`immediate: true`). |
| `dof` goes from `undefined` to a config, or back | Dispose and rebuild. Adding or removing a node needs a new graph. |
| Scene or active camera ref flips after the first build | Ignored. The existing pipeline keeps rendering. |
| Field inside `bloom` or `dof` changes | No rebuild. Deep watchers write into uniforms and `resolutionScale`; the resolution change is applied on the next frame because the nodes re-run `setSize` from `updateBefore`. |
| `antialias` changes after the first build | Ignored, with a `console.warn` asking for a reload. |

`antialias` is fixed at first build on purpose. Depth readers such as `viewportDepthTexture` (the stylized water uses one) cache a depth copy at the first pass's sample count. Rebuilding with another sample count turns them black.

Each build pushes its `bloom` / `dof` watchers into a list that `disposePipeline()` stops before the `RenderPipeline` is disposed, so a rebuild never leaves a watcher writing into a dead node. `onUnmounted` runs the same dispose.

::note
The build ends with a `console.info('[EffectComposer] pipeline built (src)', { antialias, bloomScale, dof, dofScale, outline: 'disabled' })`. This is leftover `PERF TEST` instrumentation and is marked in the source for removal. Seeing it once per DoF toggle is expected; seeing it every frame is a bug.
::

## Focus tracking runs here

The composer, not the DoF node, owns the per-frame focus update. An `onBeforeRender` callback reads the injected `useDofFocus()` target and moves the `dofFocusDistance` uniform toward it. The math is on the [Depth of field](/post-processing/depth-of-field#focus-math) page. The callback returns early when `props.dof` is `undefined`.

## Mounting outside `<Game>`

The composer injects two providers in `setup`:

- `useOutlinePass()` throws if `useOutlinePassProvider()` was not called above it.
- `useDofFocus()` returns `null` without a provider, so DoF still works with a fixed `focusDistance`.

A standalone scene therefore needs at least the outline provider:

```vue
<script setup lang="ts">
import { NoToneMapping } from 'three'
import { EffectComposer, useOutlinePassProvider, useDofFocusProvider } from '@artificer-forge/post-processing'
import { createWebGPURenderer } from '@artificer-forge/engine/runtime'

useOutlinePassProvider()
useDofFocusProvider() // optional, only if something will call setFocusTarget
</script>

<template>
  <TresCanvas :renderer="createWebGPURenderer" :tone-mapping="NoToneMapping" window-size>
    <TresPerspectiveCamera :position="[0, 10, 10]" />
    <!-- scene content -->
    <EffectComposer
      :bloom="{ strength: 0.7, radius: 0.4, threshold: 0.8, smoothWidth: 0.3 }"
      antialias="fxaa"
    />
  </TresCanvas>
</template>
```

::warning
Call the providers in the component that owns `<TresCanvas>`, or higher. `provide`/`inject` follows the Vue component tree, and `EffectComposer` injects during its own `setup`.
::
