title: Player Characters
description: Human-controlled party members with click-to-move and the action bar, and the bare player.yaml template
---

A player character is any party member the user has selected. It belongs to the `player` team, is rendered by `Character.vue`, and moves when the user clicks the floor. There is no dedicated "player" class in the engine: the leader is whichever party member `selectEntity` last promoted.

## Characteristics

| Field | Value |
|-------|-------|
| `type` | `character` |
| `team` | `player` |
| `controllable` | `true` |
| Component | `Character.vue` |
| Movement | `useCharacterController` inside `Character.vue`, driven by floor clicks from `CombatSystem.vue` |

## Where click-to-move lives

`Character.vue` owns a `useCharacterController` and exposes `moveTo`. The invisible floor plane that turns a click into a `moveTo` call is in `CombatSystem.vue`, which `<Game>` mounts by default:

```ts
// CombatSystem.vue
function handleFloorClick(event: any) {
  if (combatStore.isTargeting && aoeSystem.isActive.value) {
    abilitySystem.confirmGroundTarget()
    return
  }
  if (combatStore.isTargeting) return
  const entityId = gameStore.selectedEntityId
  if (!entityId) return
  getCharacterRef(entityId)?.moveTo(event.point)
}
```

Only the **selected** entity moves. See [Combat System](/combat/combat-system) for the floor mesh, the target indicator and the cursor.

## Visual Distinctions

- **Nameplate**: hidden while the character is selected (`isHovering && !isPlayable`). Other party members show it on hover, in cyan (`team: player`), with the live portrait, `Lv. X · Race`, HP and armor bars.
- **Outline on hover**: none for the selected character; the `party` outline preset for other party members.
- **Target indicator**: `CombatSystem.vue` renders a `TargetIndicator` at `selectedEntity.moveTarget` while a move is in progress.
- **DOF focus**: the party leader's group is the depth-of-field focus target.

## Stats

Player characters carry tabletop RPG-style stats. Companions add the action economy fields (`maxActions`, `maxBonusActions`):

```yaml
stats:
  hp: 38
  maxHp: 38
  ac: 14
  strength: 14
  dexterity: 12
  constitution: 14
  intelligence: 10
  wisdom: 12
  charisma: 12
  maxActions: 1
  maxBonusActions: 1
```

## Equipment

Weapons are attached to hand bones via `useEquipment`. The `mainHand` and `offHand` slots reference weapon `templateId` values. Modular characters also render armor slots as meshes:

```yaml
equipment:
  mainHand: shortsword
  armor: leather-jerkin
  trousers: common-pants
  boots: leather-sandals
```

## `player.yaml`

The bare player template in `apps/playground/content/entities/characters/player.yaml`. It has no class, level, portrait, abilities or equipment; it exists as the minimal `team: player` character:

```yaml
templateId: player
type: character
name: Player Character

stats:
  hp: 50
  maxHp: 50
  ac: 15
  strength: 14
  dexterity: 12
  constitution: 14
  intelligence: 10
  wisdom: 10
  charisma: 10

faction: player
team: player
controllable: true

model: /models/player.glb
rig: Rig_Medium
animations:
  idle: Idle
  walk: Walk
  run: Run
  attack: Attack
```

::note
The playground experience pages do not spawn `player`. They spawn a companion template (`cedric`) and select it. `hero` is a companion now, see [Companions](/actors/companions).
::
