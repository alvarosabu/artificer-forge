A companion is any party member the user is not currently controlling. Companions belong to the `player` team, are rendered via `Character.vue`, and become fully controllable the moment they are selected. Until then they stand where they were left.

## Characteristics

| Field | Value |
|-------|-------|
| `type` | `character` |
| `team` | `player` |
| `controllable` | `true` |
| Component | `Character.vue` |
| Party | Added via `addToParty` or `recruitEntity` |
| Behavior | None. Companions do not follow the leader |

::warning
There is no follow AI. `ai.behavior: companion` and `followDistance` appear in every companion YAML, but no code reads them. A companion moves only when it is selected and the user clicks the floor. If you need following, write it: watch `gameStore.getEntity(party.leader)?.moveTarget` and call `getCharacterRef(companionId)?.moveTo(new Vector3(...))` for each non-selected member.
::

## Visual Distinctions

:::div{class="grid grid-cols-2 gap-6 items-start"}

- **Nameplate**: cyan name (`team: player`) with live portrait, `Lv. X · Race`, HP and armor bars; shown on hover only while the companion is **not** selected
- **Outline on hover**: the `party` outline preset, only while not selected
- **PartyPanel card**: portrait with blood-fill HP overlay, white glow when selected

## Adding companions to the party

Companions are spawned in the experience page and added with `addToParty`. `loadScene` clears only non-party entities (and keeps items owned by party members), so members survive scene transitions whether they were added before or after the load.

```ts
// apps/playground/pages/character/party/experience.vue (trimmed)
const PARTY = [
  { template: 'borin', position: { x: -6, y: 0, z: 0 } },
  { template: 'fenrath', position: { x: -4, y: 0, z: 0 } },
  { template: 'cedric', position: { x: -2, y: 0, z: 0 } },
  { template: 'zynrae', position: { x: 0, y: 0, z: 0 } },
]

for (const { template, position } of PARTY) {
  const id = await gameStore.spawnFromTemplate(template, position)
  gameStore.addToParty(id)
  if (template === 'cedric') gameStore.selectEntity(id)
}
```

`addToParty` pushes the id and makes it the leader only if there is no leader yet. `selectEntity` is what promotes a member to leader afterwards.

## Recruiting and dismissing

A neutral NPC authored with `recruitable: true` can join at runtime. Two store actions flip the entity between NPC and companion:

```ts
function recruitEntity(entityId: string) {
  const entity = entities.value.get(entityId)
  if (!entity || !entity.recruitable || party.members.includes(entityId)) return
  updateEntity(entityId, {
    team: 'player',
    controllable: true,
    ai: { behavior: 'companion' },
    subtype: undefined,
  })
  addToParty(entityId)
}

function dismissEntity(entityId: string) {
  const entity = entities.value.get(entityId)
  if (!entity || !entity.recruitable || !party.members.includes(entityId)) return
  removeFromParty(entityId)
  updateEntity(entityId, {
    team: 'neutral',
    controllable: false,
    ai: { behavior: 'idle' },
    subtype: 'npc',
  })
}
```

| | `recruitEntity` | `dismissEntity` |
|---|---|---|
| Guard | `recruitable` and not in party | `recruitable` and in party |
| `team` | `'player'` | `'neutral'` |
| `controllable` | `true` | `false` |
| `ai.behavior` | `'companion'` | `'idle'` |
| `subtype` | `undefined` | `'npc'` |
| Party | `addToParty` | `removeFromParty` (leader falls to `members[0]`) |

Two getters feed the UI:

- `recruitableEntities`: entities with `recruitable: true` that are not in the party.
- `dismissableEntities`: party members with `recruitable: true`.

The playground exposes both through the command palette (`useCommands({ recruit: true })` registers a **Party** group with **Recruit** and **Dismiss** pickers built from those getters, see `apps/playground/composables/useRecruitCommands.ts`).

::note
`team` drives rendering. After `recruitEntity`, the entity leaves `actorEntities` and enters `partyEntities`, so a page that renders `partyEntities` with `Character` and `actorEntities` with `Actor` swaps the component automatically. The nameplate turns cyan and the `PartyPanel` grows a card.
::

## Switching Control

The `PartyPanel` component renders a fixed portrait card per party member. Clicking a card calls `gameStore.selectEntity(id)`, which sets `selectedEntityId` and promotes that member to `party.leader`. Floor clicks then move the newly selected character, the action bar rebuilds its slots from that character's `abilities`, and the camera follow re-targets. The previous character stays where it is.

```ts
// CharacterPanel.vue
function handleClick() {
  gameStore.selectEntity(props.member.id)
  inventory.open(props.member.id)
}
```

The selected card is highlighted with a white glow border; all others show a dimmed gold border.

## Modular companions

Three companions have no `model`. They carry an `appearance` block and are assembled from parts on the shared skeleton by `useModularRig`; their armor meshes come from whatever is equipped (`useModularArmor`). The presence of `appearance` is what switches `Character.vue`, `Actor.vue` and the portrait subject to the modular path.

```yaml
# companions/tav.yaml (trimmed)
templateId: tav
name: Tav
appearance:
  body: HUM_M_MEDIUM_Body_A
  head: HUM_M_Head_A
  hair: GEN_M_Hair_Short_A
  beard: null
  eyebrows: GEN_Eyebrows_Thin_A
  horns: null
  skinColor: '#eecbb0'
  hairColor: '#3b2417'
equipment:
  mainHand: shortsword
  armor: leather-jerkin
  trousers: common-pants
  boots: leather-sandals
```

Cedric adds a `segmentMaterials` override that swaps his right arm and hand for the `ghost` material, and Borin binds to `rig_small` because his body part is a `GOB_M_SMALL_*` mesh. Portraits for modular characters bake from the recipe plus armor, so the `portrait` field is only a placeholder while the bake runs.

## Zynrae Vexblade

Drow rogue. Dual daggers, high Dexterity. She is authored as a neutral NPC and only becomes a companion through `recruitEntity`:

```yaml
templateId: zynrae
type: character
name: Zynrae Vexblade
class: rogue
level: 1
race: Drow

team: neutral
controllable: false
recruitable: true
subtype: npc

dialogId: zynrae_alley

ai:
  behavior: idle

portrait: /img/portraits/zynrae_portrait.png
portraitBackground: /img/portraits/bgs/dark-forest.png
model: /models/characters/zynrae.glb
rig: Rig_Medium

equipment:
  mainHand: dagger
  offHand: dagger
```

In the NPC playground she is spawned five units from the leader, outside the party, and given `poisoned` so the status badges are visible:

```ts
const companionId = await gameStore.spawnFromTemplate('zynrae', {
  x: spawnPoint.x + 5,
  y: spawnPoint.y,
  z: spawnPoint.z,
})
gameStore.addStatusEffect(companionId, 'poisoned')
```
