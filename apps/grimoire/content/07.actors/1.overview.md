title: Actors
description: All characters that inhabit the world (party members, NPCs, and enemies), how they are spawned, rendered, selected and recruited

Actors are characters that exist in the game world. Each is defined by a YAML template and spawned at runtime via the game store. They share the same entity pipeline but differ in `team`, in which component renders them, and in whether they are in the party.

## Actor Types

| Role | Team | Controlled by | Component |
|------|------|---------------|-----------|
| Party member (player or companion) | `player` | Human input when selected; otherwise stands idle | `Character.vue` |
| NPC | `neutral` | None; loops an idle clip | `Actor.vue` |
| Enemy | `hostile` | None; loops an idle clip, takes damage | `Actor.vue` |

Both rendering components and the behavior composable live in the engine's runtime layer:

```ts
import { Actor, Character, useActorBehavior } from '@artificer-forge/engine/runtime'
```

::warning
There is no AI. `useActorBehavior` picks one idle animation and plays it. Companions do not follow the leader, enemies do not notice or chase the party, and nobody flees. The `ai` block in a YAML template is data the engine stores but, apart from `idleAnimation`, does not read. See [NPCs](/actors/npcs) and [Enemies](/actors/enemies).
::

## `Actor` vs `Character`

Both components load the rig (single GLB via `useGLTF`, or a modular assembly via `useModularRig` + `useModularArmor` when the entity has an `appearance`), attach equipment, status-effect overlays and particles, and show a `Nameplate` on hover. The difference is what else they carry:

| Concern | `Actor.vue` | `Character.vue` |
|---------|-------------|-----------------|
| Position | Read from the store every render | Owns a `TresGroup` moved by `useCharacterController`, synced back to the store on arrival |
| Movement | None | `moveTo`, `cancelMovement`, `onArrive` |
| Idle clip | `useActorBehavior` | Animation pack default |
| Combat | Hover outline by team | Targeting hover/click via `useCombatStore`, `showDamage`, `meleeAttack`, `attachToHand` |
| Exposed ref | None | `defineExpose` for `useSceneRefs` (`setCharacterRef`) |
| Nameplate | `isDead \|\| isHovering` | `isDead \|\| (isHovering && !isPlayable)`: the selected character has no nameplate |

Experience pages render party members with `Character` and register their refs, and everyone else with `Actor`:

```vue
<!-- apps/playground/pages/npc/basic/experience.vue (trimmed) -->
<Character
  v-for="entity in gameStore.partyEntities"
  :ref="(el: any) => setCharacterRef(entity.id, el)"
  :key="entity.id"
  :entity-id="entity.id"
/>
<Actor
  v-for="entity in gameStore.actorEntities"
  :key="entity.id"
  :entity-id="entity.id"
/>
```

`actorEntities` is every character not in the party. Some pages (party, combat) render everyone with `Character` so that enemies can receive `showDamage` calls through `useSceneRefs`.

## `useActorBehavior`

```ts
function useActorBehavior(
  entity: Ref<EntityState | undefined>,
  play: (name: AnimationNameType, fadeTime?: number, timeScale?: number) => void,
): void
```

It computes an idle clip from `entity.ai.idleAnimation`, validated against `AnimationName`, falling back to `IDLE_A`, and plays it with `fadeTime 0` whenever that name changes. It skips the play when `hp <= 0` so a corpse is not stood back up. That is the whole composable.

## How Actors Are Spawned

Actors defined in a scene YAML are spawned automatically when the scene loads:

```ts
const { spawnPoint } = await gameStore.loadScene('npc_scene')
```

Party members are spawned manually in the experience page. The playground uses the modular fighter `cedric` as the default leader:

```ts
const playerId = await gameStore.spawnFromTemplate('cedric', { x: 0, y: 0, z: 0 })
gameStore.addToParty(playerId)
gameStore.selectEntity(playerId)
```

## Selection and the party leader

`selectEntity(id)` sets `selectedEntityId` **and** promotes the entity to `party.leader` when it is a party member (`setPartyLeader` no-ops for non-party ids). The action bar, the ability system and the camera follow are all keyed off `party.leader`, so taking control of a character also moves the HUD and the camera to them.

```ts
function selectEntity(entityId: string | null) {
  selectedEntityId.value = entityId
  if (entityId) setPartyLeader(entityId)
}
```

Floor clicks move the **selected** entity (see [Combat System](/combat/combat-system)). Clicking a `CharacterPanel` card in the [Party HUD](/actors/party-hud) calls `selectEntity`.

## Recruitment

A neutral NPC with `recruitable: true` can join the party at runtime with `gameStore.recruitEntity(id)` and leave with `gameStore.dismissEntity(id)`. Both flip `team`, `controllable`, `ai.behavior` and `subtype`, then add to or remove from the party. Details and the roster are on [Companions](/actors/companions).
