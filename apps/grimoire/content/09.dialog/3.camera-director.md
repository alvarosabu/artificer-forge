title: Camera Director
description: useDialogCamera and the DialogCameraDirector component, cinematic framing that reacts to dialog state, with the exact speaker, listener and restore rules.
---

The camera director gives dialog its cinematic feel. It watches the dialog store and, every time the current node changes, tweens the active camera to frame the speaker according to the node's `cameraShot`. When the dialog ends it restores the camera to wherever it was before the conversation started.

```ts
import { DialogCameraDirector, useDialogCamera } from '@artificer-forge/engine/runtime'
```

## DialogCameraDirector

`DialogCameraDirector` is the component you drop in. It's an invisible `<TresGroup>` whose only job is to run `useDialogCamera()` from inside the canvas. The composable needs `useTresContext()` to reach the active camera, so it must live under `<TresCanvas>`.

```vue
<template>
  <!-- inside the TresCanvas / Game default slot -->
  <Character v-for="e in partyCharacters" :key="e.id" :entity-id="e.id" />
  <Actor v-for="e in actorEntities" :key="e.id" :entity-id="e.id" />

  <DialogCameraDirector />
  <Floor />
</template>
```

::warning
`DialogCameraDirector` (and `useDialogCamera`) must be mounted **inside** the `<TresCanvas>` context. Mounting it in the HUD or plain DOM means `useTresContext()` can't resolve the active camera and the framing never runs.
::

## useDialogCamera

`useDialogCamera()` is the logic. Call it directly only if you're building a custom in-canvas wrapper; otherwise use the component. It:

- Subscribes to `dialogStore.currentNodeId`. On a change to a new node it frames the new speaker; when it clears, it restores.
- Takes a one-time snapshot of the camera's pre-dialog transform and restores it on close.
- Drives all motion with a GSAP tween (`power2.inOut`), so rapid node changes interpolate from the in-flight transform rather than snapping.
- Cleans up its tween on unmount.

It returns nothing. It's a side-effecting subscription, not an API surface.

### Timing

| Move | Duration | Ease |
|------|----------|------|
| Frame a node | 0.8 s | `power2.inOut` |
| Restore on close | 0.6 s | `power2.inOut` |

A new node during a tween kills the running tween and starts from the current camera position and look-at, so fast clicking never snaps.

### Who is the speaker

The framing target comes from `node.speaker` (an entity **templateId**), never from an instance id:

1. If the store's `currentSpeakerEntity` has that `templateId`, use it. This is the entity passed to `open(dialogId, speakerId)`, so two NPCs with the same template frame the one you clicked.
2. Else the first entity in `gameStore.entities` with that `templateId`.
3. **No `speaker` on the node, or no entity matches: the camera does not move.** Narrator nodes keep the previous framing. If the first node of a tree has no speaker, no snapshot is taken until a later node has one.

`cameraTarget` is not read. See the [Dialog Engine](/dialog/dialog-engine#node-and-choice-shape) note.

### Who is the listener

The listener anchors `over-shoulder` and `two-shot`, and defines the axis for every other preset:

- Default: the **party leader** (`gameStore.party.leader`).
- If the speaker **is** the leader (a player line), the listener becomes the first entity of `type: 'character'` that is not the leader, in `entities` map order. If there is none, the leader is used, so the axis collapses and falls back to world `+Z`.
- No leader at all: no listener. The axis falls back to world `+Z` and `over-shoulder` degrades to the speaker-anchored branch at distance 3.

### Snapshot and restore

The pre-dialog transform is captured the first time a node gets framed, and only once per dialog:

- Position: the camera's exact position.
- Look-at: an approximation, `position + 1 m along the camera's forward vector`. The director does not know about OrbitControls or any other controller's target, so the restored orientation is right but the controller's internal target may differ.
- After the 0.6 s restore finishes, the snapshot is cleared so the next dialog takes a fresh one.

::note
If your page uses OrbitControls, the controls keep their own target and will re-assert it on the next user input. Disable them while `dialogStore.isOpen` if that jump bothers you.
::

## Shot presets

Each node picks its framing via `cameraShot` (default `three-quarter`). The director computes a camera position and look-at target from the speaker's world position, the listener, and the chosen preset. Values from `SHOT_PRESETS` in `useDialogCamera.ts`:

| `cameraShot` | Anchor | Distance | Side offset | Camera height | Look-at height |
|--------------|--------|----------|-------------|---------------|----------------|
| `three-quarter` | speaker | 2.8 | 2.8 | 1.85 | 1.55 |
| `over-shoulder` | listener, 3.5 behind | (uses `back`) | 1.2 | 2.1 | 1.55 |
| `closeup` | speaker | 2.2 | 0.6 | 1.7 | 1.55 |
| `wide` | speaker | 6.0 | 1.8 | 2.4 | 1.4 |
| `two-shot` | midpoint | 5.0 + separation × 0.5 | perpendicular | 2.2 | 1.4 |

The "axis" is the ground-plane unit direction from listener to speaker; the "side" is its perpendicular on the ground plane. Speaker-anchored presets place the camera at `speaker - axis × distance + side × sideOffset`, at the preset height, looking at the speaker's head. `over-shoulder` places it at `listener - axis × 3.5 + side × 1.2`. `two-shot` sits perpendicular to the midpoint between the two characters and pulls back proportional to how far apart they stand (separation is clamped to at least 1).
