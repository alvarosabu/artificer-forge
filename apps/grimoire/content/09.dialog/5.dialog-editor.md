`@artificer-forge/dialog-editor` is a Nuxt module that adds a visual node-graph editor for dialog trees to a dev server. It reads the same YAML files that the [runtime](/dialog/overview#how-a-tree-reaches-the-runtime) loads through Nuxt Content, and writes them back. It ships nothing to production: the page and API routes are only registered in dev, and every server handler refuses requests outside dev.

The editor is a Vue Flow canvas (one card per node, one edge per choice target), an inspector sidebar for the selected node and choice, and a toolbar with diagnostics and save.

## Registration

The playground registers it in `apps/playground/nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  modules: [
    // ...
    '@artificer-forge/dialog-editor',
  ],
  dialogEditor: {
    autocomplete: {
      items: { collection: 'entities', field: 'templateId', where: { type: 'item' } },
      abilities: { collection: 'abilities', field: 'abilityId' },
      statusEffects: { collection: 'statusEffect', field: 'statusEffectId' },
      classes: { collection: 'classes', field: 'classId' },
    },
  },
})
```

The package is a workspace dependency (`"@artificer-forge/dialog-editor": "workspace:*"`). Its `configKey` is `dialogEditor`.

### Options

| Option | Type | Default | Purpose |
|--------|------|---------|---------|
| `enabled` | `boolean` | `nuxt.options.dev` | Master switch. When false, `setup` returns before registering anything |
| `route` | `string` | `'/__dialog-editor'` | Path of the editor page |
| `dialogsDir` | `string` | `'content/dialogs'` | Directory scanned for `*.yaml` / `*.yml` trees, relative to `process.cwd()` |
| `layoutDir` | `string` | `'content/dialogs/.layouts'` | Directory for the JSON node-position sidecars |
| `autocomplete.skills` | `string[]` | the 18 tabletop skills from the engine's `SKILL_TO_STAT` | Suggestions for the check skill field |
| `autocomplete.items` | `AutocompleteSource` | none | Suggestions for `giveItem` / `takeItem` / `hasItem` ids |
| `autocomplete.abilities` | `AutocompleteSource` | none | Suggestions for `learnAbility` / `hasAbility` |
| `autocomplete.statusEffects` | `AutocompleteSource` | none | Suggestions for `addStatusEffect` / `removeStatusEffect` / `hasStatusEffect` |
| `autocomplete.classes` | `AutocompleteSource` | none | Suggestions for the `class` condition |

`AutocompleteSource` is `{ collection: string, field: string, where?: Record<string, unknown> }`. Each `where` entry becomes a `.where(key, '=', value)` on `queryCollection(collection)`; the distinct values of `field` become the suggestions. A source that fails to query logs a warning and leaves that list empty.

`dialogsDir` and `layoutDir` land in the private `runtimeConfig.dialogEditor`; `route` and `autocomplete` land in `runtimeConfig.public.dialogEditor`.

::note
`route` moves only the page. The four API endpoints are always under `/api/__dialog-editor/`, whatever `route` is set to.
::

### Dev-only guards

Two layers keep the editor out of production:

1. `enabled` defaults to `nuxt.options.dev`, so a production build registers no page, no components and no server handlers.
2. Every server handler starts with `if (!import.meta.dev) throw createError({ statusCode: 403 })`. Forcing `enabled: true` in a production build still gives 403 on every API call.

## Routes

| Route | Method | Purpose |
|-------|--------|---------|
| `/__dialog-editor` (the `route` option) | page | The editor UI. Registered with `extendPages` and `layout: false` |
| `/api/__dialog-editor/dialogs` | GET | Lists `{ id, file, startNode }` for every tree in `dialogsDir`, plus every flag name used across all trees (`harvestFlags`) |
| `/api/__dialog-editor/dialogs/:id` | GET | Returns `{ tree, layout, file }` for the tree whose `dialogId` is `:id`. 404 when no file declares it |
| `/api/__dialog-editor/dialogs/:id` | PUT | Body `{ tree }` (or a bare tree). Rejects with 400 when `tree.dialogId !== :id`. Writes YAML |
| `/api/__dialog-editor/dialogs/:id/layout` | PUT | Body is a `LayoutMap`. Writes `layoutDir/<id>.json`, creating the directory if needed |

## Storage model

**YAML is found by `dialogId`, not by file name.** Every GET and PUT reads all `*.yaml` / `*.yml` files in `dialogsDir`, parses each, and matches on the `dialogId` field. That is why `guard-captain.yaml` can hold `dialogId: guard_captain_gate`. On save, the PUT handler reuses the file that already declares the id; a new id gets `<id>.yaml`.

**Layout is a JSON sidecar.** Node positions live in `layoutDir/<dialogId>.json` as `{ [nodeId]: { x, y } }`. The runtime never reads this file. Nodes without a saved position get a dagre auto-layout; saved positions override it. The `__end` terminal has a position too.

**Layout saves are debounced.** Every node drag-stop emits the full position map, and `saveLayout` writes it 500 ms after the last change, without touching the dirty flag. Tree edits are separate and explicit.

**Tree saves are explicit.** Any deep mutation of the working tree sets `dirty`. Save (toolbar button or Cmd/Ctrl+S) PUTs the tree; nothing is written until then. `serializeDialog` JSON round-trips the tree first to drop `undefined` keys (so optional fields do not appear as `null`), then writes `dialogId`, `startNode`, `nodes` in that order with `lineWidth: 0`.

::warning
**Comments in the YAML are lost on save.** The editor parses the file into plain objects and re-serializes from scratch. Anything not part of the tree (comments, key order inside nodes, quoting style) does not survive a save. Keep authoring notes in the node text or in a separate file.
::

`parseDialog` is lenient: a missing `text` becomes `''`, a non-array `choices` becomes `undefined`, and unknown node keys are kept as-is. It throws only when `dialogId` or `startNode` is not a string.

## Graph model

`buildGraph(tree)` turns the tree into Vue Flow nodes and edges; `applyDagreLayout` positions them top-to-bottom (`rankdir: 'TB'`, node box 300 × 120, `nodesep: 60`, `ranksep: 90`).

- One graph node per tree node, type `dialog`, rendered by `DeDialogGraphNode`.
- One extra node with id `__end`, type `dialogEnd`, always present so it stays available as a drop target even when nothing points at it. It is synthetic: the tree never contains it, and deleting it is ignored.
- One edge per choice target, id `${source}:${handle}->${target}`.

### Handle ids

Each choice renders source handles on the right side of its node. The handle id encodes which field of which choice an edge drives:

| Handle id | Drives | Rendered when |
|-----------|--------|---------------|
| `c{i}` | `choices[i].next` | choice `i` has no `check` |
| `c{i}-ok` | `choices[i].onSuccess.next` | choice `i` has a `check` |
| `c{i}-fail` | `choices[i].onFailure.next` | choice `i` has a `check` |
| `bundle` | nothing | node is collapsed; all outgoing edges are re-routed through it for display |

`wireChoiceTarget(node, handle, target)` and `clearChoiceTarget(node, handle)` in `utils/createNode.ts` are the only two places that map a handle back to a choice field. Dropping on `bundle` is rejected, so you must expand a node before rewiring one of its choices.

### Edge kinds

| `data.kind` | Meaning | CSS class |
|-------------|---------|-----------|
| `plain` | `choice.next` to a node | `e-plain` |
| `success` | `onSuccess.next` | `e-ok` |
| `failure` | `onFailure.next` | `e-fail` |
| `end` | any target that is `__end` (overrides the three above) | `e-end` |

Node expansion state (`useNodeExpansion`) is a module-level reactive singleton shared by the node cards and the canvas. Vue Flow does not reliably propagate `:nodes` data changes into rendered nodes, so the cards read it directly.

## Editing gestures

| Gesture | Result |
|---------|--------|
| Click a node | Selects it; the inspector shows its fields |
| Drag a node | Moves it; positions are saved (debounced) on drop |
| Drag a node onto an edge A→B (within 48 flow units of the segment) | **Splice**: A's choice re-points to the dragged node C, and C gains a plain choice `New choice → B`. The edge highlights while hovering. Edges touching C are ignored |
| Drag from a choice handle to another node's top handle | **Rewire** that choice's target |
| Drag from a choice handle and release on empty canvas | **Spawn** a new downstream node `node_N` wired from that choice, placed at the drop point |
| Drag from a node's top (target) handle to empty canvas | Spawn a new upstream node with one choice `New choice → this node` |
| Grab an existing edge end and drop on another handle | **Reconnect** (Blender style). Clears the old choice field and wires the new one. Aborts without change if the new handle is invalid (e.g. a collapsed bundle) |
| Grab an existing edge end and drop on empty canvas | **Detach**: clears the choice's `next` (or branch `next`) but keeps the choice text, conditions and check |
| `Delete` / `Backspace` with a node selected | Deletes the node from the tree and clears every choice that pointed at it (`detachReferencesTo`), so no edge silently reconnects to a future node reusing the id. Its saved position is dropped too |
| `Cmd+S` / `Ctrl+S` | Saves the tree when dirty. `preventDefault` stops the browser save dialog |
| `▸` / `▾` on a card, or **Expand all** / **Collapse all** | Toggles per-choice handles. Collapsed cards show `N choices · M checks` and a single bundle handle |

New node ids come from `nextNodeId`: the first free `node_N`. The toolbar's **+ Node** input accepts `[\w-]+` and rejects an id that already exists.

**+ New dialog** prompts for a `dialogId` and a start node id (default `start`), PUTs a one-node tree, refreshes the list and opens it. The editor auto-loads the first dialog in the list on mount.

## Inspector

Selecting a node shows its fields; clicking a choice row below shows that choice.

| Node field | Bound to | Notes |
|------------|----------|-------|
| Speaker | `node.speaker` | Free text, entity `templateId`; blank = narrator |
| Camera shot | `node.cameraShot` | Select from the five presets or none |
| Camera target | `node.cameraTarget` | Stored but [not read by the camera](/dialog/dialog-engine#node-and-choice-shape) |
| Text | `node.text` | Textarea |
| On-entry effects | `node.effects` | `DeEffectBuilder` |

| Choice field | Bound to | Notes |
|--------------|----------|-------|
| Choice text | `choice.text` | |
| Tag prefix | `choice.tagPrefix` | |
| Skill check (checkbox) | `choice.check` | Turning on sets `{ skill: 'persuasion', dc: 10 }`, moves `next` into `onSuccess.next`, sets `onFailure.next = '__end'` and deletes `next`. Turning off restores `next` from `onSuccess.next` and deletes `check`, `onSuccess`, `onFailure` |
| Skill / DC / adv | `check.skill`, `check.dc`, `check.advantage` | Skill has a datalist from `autocomplete.skills` |
| On success → node / Success effects | `onSuccess.next`, `onSuccess.effects` | Select lists every node id plus `__end` |
| On failure → node / Failure effects | `onFailure.next`, `onFailure.effects` | |
| Next node | `choice.next` | Only when there is no check |
| Conditions (all must pass) | `choice.conditions` | `DeConditionBuilder` |
| Effects (on choose) | `choice.effects` | `DeEffectBuilder` |
| Locked display | `choice.lockedDisplay` | `lock` (default) or `hide` |

**+ choice** appends `{ text: 'New choice', next: '__end' }`. Builders mutate the reactive tree in place, so every keystroke marks the tree dirty through the deep watch. Removing the last row of a builder deletes the field instead of leaving an empty array.

### ConditionBuilder DSL

One row is one condition object with a single key. Changing the key resets the row to that key's default.

| Key | Row default | Inputs |
|-----|-------------|--------|
| `flag` | `{ flag: '' }` | flag name (datalist of harvested flags) |
| `notFlag` | `{ notFlag: '' }` | flag name |
| `class` | `{ class: '' }` | class id (datalist from `autocomplete.classes`) |
| `race` | `{ race: '' }` | free text |
| `faction` | `{ faction: '' }` | free text |
| `hasAbility` | `{ hasAbility: '' }` | ability id (datalist) |
| `hasStatusEffect` | `{ hasStatusEffect: '' }` | status id (datalist) |
| `stat` | `{ stat: { strength: { gte: 10 } } }` | stat (`strength`, `dexterity`, `constitution`, `intelligence`, `wisdom`, `charisma`), op (`gte`, `lte`, `gt`, `lt`, `eq`), number |
| `partyHas` | `{ partyHas: '' }` | class or templateId |
| `hasItem` | `{ hasItem: { id: '', qty: 1 } }` | item id (datalist), quantity |

The builder writes only the string form of `flag`. The object form `{ flag: { name: value } }` that the [engine](/dialog/dialog-engine#conditions) also accepts must be typed in YAML by hand; the builder preserves it on load but shows an empty flag input for such a row.

### EffectBuilder DSL

| Key | Row default | Inputs |
|-----|-------------|--------|
| `setFlag` | `{ setFlag: { newFlag: true } }` | flag name, value `true` / `false`. Numeric values are kept on load but the select shows only the two booleans |
| `clearFlag` | `{ clearFlag: '' }` | flag name |
| `addStatusEffect` | `{ addStatusEffect: { entity: 'player', id: '' } }` | entity `player` / `speaker`, status id |
| `removeStatusEffect` | `{ removeStatusEffect: { entity: 'player', id: '' } }` | same |
| `learnAbility` | `{ learnAbility: '' }` | ability id |
| `giveItem` | `{ giveItem: { id: '', qty: 1 } }` | item id, quantity |
| `takeItem` | `{ takeItem: { id: '', qty: 1 } }` | item id, quantity |
| `endDialog` | `{ endDialog: true }` | none |

Flag suggestions come from `harvestFlags`, which scans every tree in `dialogsDir` for `flag`, `notFlag`, `clearFlag` and `setFlag` names. A new flag typed anywhere joins the list after the next save (the list refreshes on save).

## Diagnostics

`validateTree(tree)` runs on every change and feeds the toolbar counter (`⚠ N issues` or `✓ no issues`). Diagnostics are advisory; save is never blocked.

| `kind` | Trigger | Message |
|--------|---------|---------|
| `missing-start` | `startNode` is not a node id | `startNode "x" does not exist` |
| `dead-end` | a node has zero choices | `node "x" has no choices` |
| `broken-link` | a `next`, `onSuccess.next` or `onFailure.next` names a node that does not exist (`__end` is allowed) | `choice points to missing node "x"` |
| `unreachable` | a node is not reachable from `startNode` by BFS over valid targets | `node "x" is unreachable from startNode` |

A `dead-end` node is not a bug at runtime: the panel shows its line with no choices, and the player can only close with Escape. Add a choice with `next: __end` to give a clean exit.

## Auto-registered components and composables

The module registers its runtime with `addComponentsDir({ prefix: 'De', global: false })` and `addImportsDir('runtime/composables')`, so these names are available in the host app without imports:

| Name | Kind | Role |
|------|------|------|
| `DeEditorToolbar` | component | Dialog picker, new dialog, add node, expand/collapse, diagnostics, save |
| `DeDialogGraphCanvas` | component | Vue Flow wrapper; emits `select`, `layout-change`, `rewire`, `disconnect`, `reconnect`, `delete-node`, `create-node`, `splice` |
| `DeDialogGraphNode` | component | One node card with per-choice handles |
| `DeDialogInspector` | component | Sidebar for the selected node and choice |
| `DeConditionBuilder` | component | Props `owner`, `field`, plus suggestion lists; mutates `owner[field]` |
| `DeEffectBuilder` | component | Same contract for effects |
| `useDialogEditor()` | composable | Working tree, layout, selection, dirty/saving flags, graph, diagnostics and every structural edit |
| `useAutocomplete()` | composable | `skills`, `items`, `abilities`, `statusEffects`, `classes` refs and `load()` |
| `useNodeExpansion()` | composable | Shared expanded-state singleton |

You can reuse `useDialogEditor` and the `De*` components to build a different layout (for example an embedded editor inside a level tool) without the default page.

The pure helpers (`parseDialog`, `serializeDialog`, `buildGraph`, `applyDagreLayout`, `validateTree`, `harvestFlags`, `nextNodeId`, `wireChoiceTarget`, `spliceNode`, ...) live in `src/runtime/utils/` and are covered by Vitest in `packages/dialog-editor/test/`. Run them with `pnpm -F @artificer-forge/dialog-editor test`.

::note
The module keeps its **own copy** of `DialogTree`, `DialogNode`, `DialogChoice` and `DialogCheck` in `packages/dialog-editor/src/types.ts`. It does not import them from `@artificer-forge/engine`, and the package entry exports only `ModuleOptions` and `AutocompleteSource`. The two copies match today; a new condition or effect key added to `useDialogEngine` must also be added to `ConditionBuilder.vue` / `EffectBuilder.vue` by hand, or the editor will not offer it.
::
