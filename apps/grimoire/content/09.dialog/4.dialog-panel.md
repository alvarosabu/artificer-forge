title: Dialog Panel
description: The DialogPanel HUD component. It renders the active line, speaker portrait, choices, and skill-check feedback, and is mounted for you by Hud.
---

`DialogPanel` is the 2D overlay that renders an active dialog: the speaker's portrait and name, the current line, and the clickable choices. It's a pure consumer of `useDialogStore`. It reads state and calls `choose` / `close`, holding no dialog logic of its own.

```ts
import { DialogPanel } from '@artificer-forge/engine/ui'
```

## Usage

`Hud` (from `@artificer-forge/engine/ui`) already renders `<DialogPanel />` next to the action bar, inventory modal and context menus, and `<Game>` renders `Hud`. If your page runs inside `<Game>` there is nothing to mount.

Mount it yourself only when you build a custom overlay without `Hud`. It goes in the HUD layer (the DOM overlay, not the canvas). It teleports itself to `<body>` and pins to the bottom-center of the screen, so placement in your template is just about where it lives in the component tree, not on-screen position.

```vue
<script setup lang="ts">
import { DialogPanel } from '@artificer-forge/engine/ui'
</script>

<template>
  <!-- custom HUD without <Hud> -->
  <DialogPanel />
</template>
```

::warning
Mounting `DialogPanel` in a page that also uses `<Game>` renders two panels stacked on top of each other. Both react to the same store, so both respond to clicks and keys.
::

It takes no props. Everything comes from the store. The panel only shows while `dialogStore.isOpen` is true, animating in and out with a slide/fade transition.

## What it renders

- **Portrait**: a live-baked 3D portrait of the current speaker via `usePortraitRenderer` (the same source the action bar and character panel use), falling back to the speaker's first initial when there's no image yet (e.g. a Narrator).
- **Speaker name**: `currentSpeakerEntity?.name`, defaulting to `Narrator`.
- **Line**: `dialogStore.currentText`.
- **Choices**: one button per `currentChoices` entry. Each shows its number, an optional `[tagPrefix]` label, a `[SKILL DC]` badge for check choices, the choice text, and, for locked choices, the `lockedReason`. Unavailable choices render dimmed and disabled.
- **Check flash**: when a skill check resolves, `lastCheck` drives a brief badge showing the skill, DC, the roll math (`roll±modifier = total`), and SUCCESS / FAILURE. The store clears it after 2.5 s.

### Label formatting

- The check badge is `checkLabel(raw)`: the skill with hyphens replaced by spaces, upper-cased, then the DC. `sleight-of-hand` at DC 12 renders as `[SLEIGHT OF HAND 12]`.
- The `[tagPrefix]` label is **suppressed** when it equals the check's skill (case-insensitive). `tagPrefix: INTIMIDATION` next to `check.skill: intimidation` shows only the `[INTIMIDATION 14]` badge, not both. A different prefix (`SCHOLAR` on a `history` check) shows both.
- The check flash badge upper-cases the skill but keeps hyphens (`SLEIGHT-OF-HAND 12`).

## Input

The panel binds keyboard shortcuts while a dialog is open:

| Key | Action | Guard |
|-----|--------|-------|
| `1`–`9` | Pick the matching visible choice (if available) | Ignored when focus is in an `input`, `textarea`, `select` or contenteditable (`isEditableTarget`) |
| `Escape` | Close the dialog | None |

The digit maps to the **visible** list position (`visibleChoices[idx]`), then the click calls `dialogStore.choose(choice.index)` with the choice's original `index`. That index is stable even when hidden choices are filtered out, so the store picks the right choice.

`isEditableTarget` comes from `@artificer-forge/engine/runtime` (`keyboard.ts`). The guard exists so typing a digit into a debug or chat input does not pick a dialog choice. Escape has no such guard and always closes.

::note
`DialogPanel` is part of `@artificer-forge/engine/ui`, the Nuxt UI based HUD layer. It uses `UIcon` for the check-result badge, so the consuming app must have `@nuxt/ui` installed (an optional peer of the engine).
::
