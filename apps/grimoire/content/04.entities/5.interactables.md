title: Interactables

Interactables are world objects the player clicks: chests, doors, levers. They have no baked clips. The `Interactable` component rotates a named mesh between states declared in the template, so angles and timing change in YAML, not in Blender.

```vue
<script setup lang="ts">
import { Interactable, useGameStore, useSceneRefs } from '@artificer-forge/engine/runtime'

const gameStore = useGameStore()
const { setInteractableRef } = useSceneRefs()
const interactableEntities = computed(() =>
  [...gameStore.entities.values()].filter(e => e.type === 'interactable'),
)

function onInteract(entityId: string) {
  // e.g. open the loot popover, or getInteractableRef(entityId)?.toggle()
}
</script>

<template>
  <Interactable
    v-for="entity in interactableEntities"
    :key="entity.id"
    :ref="(el: any) => setInteractableRef(entity.id, el)"
    :entity-id="entity.id"
    @interact="onInteract"
  />
</template>
```

## Component API

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `entityId` | `string` | required | Store entity to render |
| `debug` | `boolean` | `false` | Draws the BVH (`useBVH` from cientos) used for fast raycasts |

| Emit | Payload | When |
|------|---------|------|
| `interact` | `entityId: string` | Left click on the model. The component does not toggle itself; the parent decides |

| Exposed | Purpose |
|---------|---------|
| `toggle()` | Advance to the next state and write `opened` to the store |

`InteractableRef` in `useSceneRefs` is `{ toggle }`.

Behaviour on pointer events: hover adds the model to the outline pass with the `interactive` preset and shows an `<Html>` label with `name` and an HP bar (`hp / maxHp`). Right click opens the [entity context menu](/core-concepts/commands) (Open, Close, Lockpick, Attack, …).

## Template

```yaml
# content/entities/interactables/chest-common.yaml
templateId: chest_common
type: interactable
subtype: container
name: Wooden Chest

locked: false
lockDifficulty: 0

hp: 20
maxHp: 20
destructible: true

model: /models/interactables/Chest.glb
animations:
  default: closed
  states:
    closed:
      target: chest_lid
      rotation: { x: 0, y: 0, z: 0 }  # values are Math.PI multipliers
    open:
      target: chest_lid
      rotation: { x: -0.6, y: 0, z: 0 }  # -0.6π ≈ -108°

lootTable:
  - id: healing_potion
    quantity: 1
    chance: 1.0
```

`Chest.glb` ships in `@artificer-forge/assets` (`files/models/interactables/`), served at `/models/interactables/Chest.glb`.

The `animations` block: `default` names the starting state; each state names the mesh to move (`target`) and its rotation as **PI multipliers** (`-0.6` → `-0.6 * Math.PI` ≈ -108°).

::warning
The schema also accepts a `position` per state, but the component only lerps `rotation`. A state `position` is stored and ignored.
::

## How the component works

1. `useGLTF(entity.model, { draco: true })` loads the model; `useBVH` builds an acceleration structure on the scene.
2. `useGraph(scene)` builds a name → object dictionary. The target mesh is `graph.nodes[states[default].target]`, so `chest_lid` is looked up directly instead of traversing.
3. `currentState` starts at `animations.default` (fallback `'closed'`). `targetRotation` is the current state's rotation times `Math.PI`.
4. Every frame (`useLoop().onBeforeRender`), the mesh rotation lerps toward the target:

```ts
const LERP_SPEED = 8

mesh.rotation.x = MathUtils.lerp(mesh.rotation.x, targetRotation.value.x, delta * LERP_SPEED)
// same for y and z
```

5. `toggle()` cycles through `Object.keys(states)` in declaration order (`closed → open → closed`) and calls `gameStore.updateEntity(entityId, { opened: currentState === 'open' })`. Any number of states works; only the `open` name is special for the store flag.

Only the `target` of the **default** state is looked up. All states of one interactable must animate the same mesh.

## Placement

The group binds `entity.position` from the store. `entity.rotation` (from a scene's `rotation`) is **not** applied to interactables; orient the chest in Blender or in the GLB.

Interactables are placed by [scenes](/entities/scenes) or spawned directly:

```ts
await gameStore.spawnFromTemplate('chest_common', { x: 2, y: 0, z: 2 })
```

## Model requirements

- The animated part is a **named mesh** whose name equals the YAML `target`. Names are case-sensitive: `Lid` ≠ `lid` ≠ `chest_lid`.
- Export in the default state; state rotations are absolute values relative to it.
- Apply transforms in Blender before export, or the lerp starts from an offset.

## Containers and loot

Interactables with `subtype: container` are containers in the inventory system. `spawnFromTemplate` rolls the `lootTable` once and spawns each surviving entry as an item entity with `containerId = chestId`:

```yaml
lootTable:
  - id: healing_potion       # item templateId
    quantity: [1, 3]         # uniform random range, or a fixed number
    chance: 0.8              # 0.0 – 1.0
```

`gameStore.itemsIn(chestId)` returns those items; the loot popover and `moveItem` treat them like any other item ([Loot](/inventory/loot)).

A character with `hp <= 0` (or `dead: true`) is looted the same way, equipped slots included ([Loot: corpses](/inventory/loot#corpses-as-containers)).
