---
title: Entity Templates
description: The full entities collection schema, real character, item and interactable templates from the playground, and the useEntityTemplates query helpers.
---

Templates are YAML files under `content/entities/` that define **what** an entity is. [Scenes](/entities/scenes) define **where** instances are placed. Runtime state lives in the [Game Store](/core-concepts/game-store).

The schema below is `apps/playground/content.config.ts`, collection `entities`, with nested `{ x, y, z }` objects and the equipment slot list shortened. Every field except `templateId`, `type` and `name` is optional.

## Schema

::code-group

```ts [Identity and character]
templateId: z.string()
type: z.enum(['character', 'item', 'interactable'])
subtype: z.string().optional()          // enemy | npc | weapon | armor | boots | container …
name: z.string()
class: z.string().optional()            // classId (fighter, rogue)
level: z.number().optional()
race: z.string().optional()
sex: z.enum(['M', 'F']).optional()      // picks the fitted armor mesh (assets.M / assets.F)
faction: z.string().optional()
team: z.enum(['player', 'ally', 'neutral', 'hostile']).optional()   // default 'neutral'
controllable: z.boolean().optional()
recruitable: z.boolean().optional()     // enables recruitEntity / dismissEntity
stats: z.record(z.number()).optional()  // hp, maxHp, ac, strength … maxActions, maxBonusActions
ai: z.object({ behavior: z.string() }).passthrough().optional()
abilities: z.array(z.string()).optional()   // abilityIds, appended to melee-attack, dash, throw
dialogId: z.string().optional()
```

```ts [Rendering]
portrait: z.string().optional()            // static portrait image
portraitBackground: z.string().optional()  // backdrop texture for the baked portrait
icon: z.string().optional()                // inventory cell image (items)
model: z.string().optional()               // single-GLB path (characters, weapons, interactables)
rig: z.string().optional()                 // node name inside the GLB: Rig_Medium | Rig_Large
appearance: z.object({                     // modular character recipe; presence replaces `model`
  body: z.string(),
  head: z.string(),
  hair: z.string().nullable().optional(),
  beard: z.string().nullable().optional(),
  eyebrows: z.string().nullable().optional(),
  accessory: z.string().nullable().optional(),
  horns: z.string().nullable().optional(),
  skinColor: z.string(),
  hairColor: z.string(),
  hornColorA: z.string().optional(),
  hornColorB: z.string().optional(),
  hornPattern: z.enum(['gradient', 'repeated', 'solid']).optional(),
  hornWeight: z.number().optional(),
  equipmentTint: z.record(z.string()).optional(),   // slot -> texture.tints[].id
  segmentMaterials: z.array(z.object({
    segments: z.array(z.string()),
    material: z.string(),
    params: z.record(z.any()).optional(),
  })).optional(),
}).optional()
animations: z.object({                     // interactables only: code-driven transforms
  default: z.string(),
  states: z.record(z.object({
    target: z.string(),
    rotation: z.object({ x, y, z }).optional(),
    position: z.object({ x, y, z }).optional(),
  })),
}).optional()
```

```ts [Item]
damage: z.object({ dice: z.string(), type: z.string() }).optional()
properties: z.array(z.string()).optional()
range: z.object({ normal: z.number(), long: z.number() }).optional()
effect: z.object({ type: z.string(), dice: z.string().optional(), bonus: z.number().optional() }).optional()
armor: z.object({ physical: z.number().optional(), magical: z.number().optional() }).optional()
modular: z.object({                        // body-worn gear on modular characters
  slot: z.enum(['helmet', 'armor', 'cloak', 'trousers', 'gauntlets', 'boots']),
  hides: z.array(z.enum([
    'head', 'torso', 'hips',
    'arm', 'armL', 'armR', 'hand', 'handL', 'handR',
    'leg', 'legL', 'legR', 'foot', 'footL', 'footR',
  ])),
  rig: z.enum(['medium', 'small']).optional(),   // absent = medium
  assets: z.object({ M: z.string().optional(), F: z.string().optional(), any: z.string().optional() }).optional(),
}).optional()
texture: z.object({                        // palette atlas + recolours
  base: z.string(),
  tints: z.array(z.object({ id: z.string(), label: z.string(), map: z.string() })).optional(),
}).optional()
weight: z.number().optional()
value: z.number().optional()
usable: z.boolean().optional()
stackable: z.boolean().optional()
maxStack: z.number().optional()
requirements: z.record(z.number()).optional()
```

```ts [Interactable and equipment]
locked: z.boolean().optional()
lockDifficulty: z.number().optional()
hp: z.number().optional()                  // fallback when stats.hp is absent
maxHp: z.number().optional()
destructible: z.boolean().optional()
lootTable: z.array(z.object({
  id: z.string(),                          // item templateId
  quantity: z.union([z.number(), z.array(z.number())]).optional(),
  chance: z.number(),
})).optional()
equipment: z.object({                      // starting gear, one item templateId per slot
  mainHand, offHand, helmet, armor, cloak, trousers,
  gauntlets, boots, amulet, ring1, ring2   // all z.string().optional()
}).optional()
equipmentSlots: z.array(z.enum([           // slots this character owns (drives the doll + moveItem 'no-slot')
  'mainHand', 'offHand', 'helmet', 'armor', 'cloak', 'trousers',
  'gauntlets', 'boots', 'amulet', 'ring1', 'ring2',
])).optional()
```

::

::note
`hp`/`maxHp` resolve as `stats.hp ?? hp`. Characters put them in `stats`; interactables use the top-level fields.
::

::warning
Only `ai` accepts extra keys (`.passthrough()`), which is where `followDistance`, `alertRange` and `idleAnimation` live. `orc_scout.yaml` still carries a top-level `drops:` list, and `hero.yaml` / `orc_scout.yaml` a flat `animations:` map from before the interactable schema; no code reads either.
::

## Character templates

### Modular companion (`tav.yaml`)

No `model`. The `appearance` block names parts from the [assets package](/characters/assets-package); visible armor comes from `equipment`.

```yaml
# content/entities/characters/companions/tav.yaml
templateId: tav
type: character
name: Tav
class: fighter
level: 1
race: human
sex: M

stats:
  hp: 38
  maxHp: 38
  ac: 14
  strength: 12
  dexterity: 16
  constitution: 12
  intelligence: 10
  wisdom: 14
  charisma: 10
  maxActions: 1
  maxBonusActions: 1

team: player
controllable: true

ai:
  behavior: companion
  followDistance: 3

portrait: /img/portraits/hero_portrait.png
portraitBackground: /img/portraits/bgs/blue-storm.png

appearance:
  body: HUM_M_MEDIUM_Body_A
  head: HUM_M_Head_A
  hair: GEN_M_Hair_Short_A
  beard: null
  eyebrows: GEN_Eyebrows_Thin_A
  horns: null
  skinColor: '#eecbb0'
  hairColor: '#3b2417'

abilities:
  - arrow-shot
  - magic-missile
  - fireball

equipmentSlots:
  - mainHand
  - offHand
  - helmet
  - armor
  - trousers
  - gauntlets
  - boots
  - amulet
  - ring1
  - ring2

equipment:
  mainHand: shortsword
  armor: leather-jerkin
  trousers: common-pants
  boots: leather-sandals
```

Hex colours start with `#`, which YAML reads as a comment. Quote them.

`cedric.yaml` adds a per-segment material swap for his ghost arm:

```yaml
appearance:
  body: HUM_M_MEDIUM_Body_A
  head: HUM_M_Head_Cedric
  hair: GEN_M_Hair_Long_A
  beard: null
  eyebrows: GEN_Eyebrows_Thin_A
  horns: null
  skinColor: '#eecbb0'
  hairColor: '#2c222b'
  segmentMaterials:
    - segments: [armR, handR]
      material: ghost
      params: { color: '#88ccff', glowStrength: 12, fresnelPower: 1.2 }
```

`borin.yaml` is a small-rig goblin (`body: GOB_M_SMALL_Body_A`): the body id selects `rig_small.glb` and the `Rig_Small` animation packs.

### Single-GLB companion (`hero.yaml`)

```yaml
# content/entities/characters/companions/hero.yaml
templateId: hero
type: character
name: Hero
class: fighter
level: 1
race: Human

stats: { hp: 38, maxHp: 38, ac: 14, strength: 12, dexterity: 16, constitution: 12,
         intelligence: 10, wisdom: 14, charisma: 10, maxActions: 1, maxBonusActions: 1 }

team: player
controllable: true

ai:
  behavior: companion
  followDistance: 3

portrait: /img/portraits/hero_portrait.png
portraitBackground: /img/portraits/bgs/blue-storm.png
model: /models/characters/hero.glb
rig: Rig_Medium
abilities:
  - arrow-shot
  - magic-missile
  - fireball

equipmentSlots:
  - mainHand
  - offHand
  - helmet
  - armor
  - gauntlets
  - boots
  - amulet
  - ring1
  - ring2

equipment:
  mainHand: shortsword
  armor: breastplate
  ring1: ring-of-warding
```

`rig` must match a node name inside the GLB. `fenrath.yaml` uses `rig: Rig_Large`, which also switches the animation packs to `Rig_Large`.

### Enemy (`orc_scout.yaml`)

```yaml
# content/entities/characters/enemies/orc_scout.yaml
templateId: orc_scout
type: character
subtype: enemy
name: Orc Scout
level: 1
race: Orc

stats:
  hp: 24
  maxHp: 24
  ac: 13
  strength: 8
  dexterity: 14
  constitution: 10
  intelligence: 8
  wisdom: 8
  charisma: 6

faction: orc
team: hostile
controllable: false

ai:
  behavior: aggressive
  alertRange: 10
  attackRange: 5
  fleeThreshold: 0.2

model: /models/characters/orc.glb
rig: Rig_Medium

equipmentSlots:
  - mainHand
  - armor
  - ring1

equipment:
  mainHand: orc_axe
  armor: breastplate
  ring1: ring-of-warding
```

Equipped `armor` items feed the armor pools: `breastplate` (20 physical, 3 magical) + `ring-of-warding` (2 physical, 15 magical) give the orc 22/18 armor on top of 24 HP. `alertRange`, `attackRange` and `fleeThreshold` are stored but no engine code reads them yet.

### Recruitable NPC (`zynrae.yaml`, excerpt)

```yaml
team: neutral
controllable: false
recruitable: true
subtype: npc
dialogId: zynrae_alley
```

`recruitEntity(id)` flips `team: player`, `controllable: true`, `ai.behavior: companion`, clears `subtype`, and adds the entity to the party.

## Item templates

### Weapon (`shortsword.yaml`)

Weapons need `model`: [useEquipment](/characters/equipment) loads it and parents it to the hand bone.

```yaml
# content/entities/items/weapons/shortsword.yaml
templateId: shortsword
type: item
subtype: weapon
name: Shortsword
icon: /img/items/shortsword.png
model: /models/items/weapons/Sword_1Handed.glb
damage:
  dice: "1d8"
  type: slashing
properties:
  - versatile
weight: 3
value: 15
```

### Modular armor (`leather-jerkin.yaml`)

Body-worn gear has no `model`. `modular.assets` names one fitted GLB per body sex; `hides` lists the body segments the mesh covers; `texture.tints` lists alternate palette atlases.

```yaml
# content/entities/items/armor/leather-jerkin.yaml
templateId: leather-jerkin
type: item
subtype: armor
name: Leather Jerkin
modular:
  slot: armor
  hides: [torso]
  assets:
    M: /models/characters/armors/ARM_M_Leather_Jerkin.glb
    F: /models/characters/armors/ARM_F_Leather_Jerkin.glb
texture:
  base: /models/characters/textures/leather_jerkin_texture.png
  tints:
    - { id: black, label: Black, map: /models/characters/textures/leather_jerkin_black.png }
    - { id: crimson, label: Crimson, map: /models/characters/textures/leather_jerkin_crimson.png }
armor:
  physical: 8
weight: 6
value: 45
```

Other real patterns in `items/armor/`:

| File | Notable fields | Why |
|------|----------------|-----|
| `cedric-boots.yaml` | `assets: { any: … }`, `hides: [foot]` | unisex mesh that brings its own feet |
| `cedric-gauntlet.yaml` | `hides: [armL]` | left hand only; the right arm is the ghost arm |
| `cedric-cloak.yaml` | `hides: []` | drapes over the back, covers nothing |
| `wild-raider-armor.yaml` | `rig: small` | goblin gear; skipped on medium bodies |
| `breastplate.yaml`, `ring-of-warding.yaml` | no `modular` | stat-only, nothing rendered on the body |

`subtype` must match the slot: `moveItem` rejects a `boots` item dropped on the `armor` slot with `wrong-type`. Mapping: `weapon` → mainHand/offHand, `ring` → ring1/ring2, otherwise `subtype === slot`.

### Consumable (`healing_potion.yaml`)

```yaml
# content/entities/items/consumables/healing_potion.yaml
templateId: healing_potion
type: item
subtype: consumable
name: Healing Potion
icon: /img/items/potion_health_medium.png

  type: heal
  dice: 2d4
weight: 0.5
value: 50
usable: true
stackable: true
maxStack: 10
```

## Interactable template (`chest-common.yaml`)

```yaml
# content/entities/interactables/chest-common.yaml
templateId: chest_common
type: interactable
subtype: container
name: Wooden Chest

locked: false
lockDifficulty: 0

hp: 20
maxHp: 20
destructible: true

model: /models/interactables/Chest.glb
animations:
  default: closed
  states:
    closed:
      target: chest_lid
      rotation: { x: 0, y: 0, z: 0 }  # values are Math.PI multipliers
    open:
      target: chest_lid
      rotation: { x: -0.6, y: 0, z: 0 }  # -0.6π ≈ -108°

lootTable:
  - id: healing_potion
    quantity: 1
    chance: 1.0
```

See [Interactables](/entities/interactables) for how the `animations` block drives the lid.

## Querying templates

`apps/playground/composables/useEntityTemplates.ts` wraps the common queries:

| Helper | Query |
|--------|-------|
| `getAll()` | every template |
| `getCharacters()` | `type = character` |
| `getEnemies()` | `type = character` and `hostile = true` |
| `getCompanions()` | `type = character`, `controllable = true`, `hostile = false` |
| `getNPCs()` | `type = character`, `subtype = npc` |
| `getItems()` | `type = item` |
| `getWeapons()` | `type = item`, `subtype = weapon` |
| `getInteractables()` | `type = interactable` |
| `getTemplateById(templateId)` | `.first()` by `templateId` |

::caution
`getEnemies()` and `getCompanions()` filter on a `hostile` field that does not exist in the schema. Filter on `team` (`'hostile'`, `'player'`) until the composable is fixed.
::

Most engine code does not use this composable. It goes through `gameStore.resolveTemplate(templateId)`, which calls the injected `ContentSource` ([Overview](/entities/overview)).
