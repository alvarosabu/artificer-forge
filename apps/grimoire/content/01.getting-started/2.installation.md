`@artificer-forge/engine` ships its Vue/TS source uncompiled and is compiled by the host Nuxt 4 app. This page lists the modules, build config, plugins and styles the playground uses to run it. Follow it as a checklist for a new app.

## Install

The engine is **workspace-only**. It is not published to npm. Add it as a workspace dependency in the app's `package.json`:

```json [package.json]
{
  "dependencies": {
    "@artificer-forge/engine": "workspace:*",
    "@artificer-forge/assets": "workspace:*",
    "@artificer-forge/post-processing": "workspace:*",
    "@artificer-forge/vfx": "workspace:*"
  }
}
```

Then run `pnpm install` from the repo root. `post-processing` and `vfx` are regular dependencies of the engine, but the playground also lists them so it can import from them directly (`useDofFocus`, `ghostMaterial`).

::note
`@artificer-forge/vfx` and `@artificer-forge/utils` resolve to `dist/`. Build them once (`pnpm -F @artificer-forge/vfx build`) or their imports fail. The engine and post-processing resolve to `src/` and need no build.
::

## Nuxt Modules

From `apps/playground/nuxt.config.ts`:

| Module | Required | Why |
|--------|----------|-----|
| `@tresjs/nuxt` | yes | `<TresCanvas>` and auto-imported Tres components |
| `@pinia/nuxt` | yes | `useGameStore` and the other engine stores |
| `@nuxt/ui` | for `/ui` | The HUD layer is built on Nuxt UI. Optional peer of the engine |
| `@artificer-forge/assets/nuxt` | yes | Serves `/models/**` and `/textures/**` from the assets package and generates `#build/character-parts.mjs` for modular characters |
| `@nuxt/content` | app choice | The engine never queries content itself. The playground uses Nuxt Content as its content source (see below); any async source works |
| `@artificer-forge/dialog-editor` | optional | Dev-only visual dialog editor at `/__dialog-editor` |
| `@nuxt/devtools`, `@nuxt/eslint` | optional | Tooling |

## Configuration

::code-group

```ts [nuxt.config.ts]
import { createResolver } from '@nuxt/kit'
const { resolve } = createResolver(import.meta.url)

export default defineNuxtConfig({
  modules: [
    '@nuxt/eslint',
    '@tresjs/nuxt',
    '@nuxt/content',
    '@nuxt/devtools',
    '@nuxt/ui',
    '@pinia/nuxt',
    '@artificer-forge/dialog-editor',
    '@artificer-forge/assets/nuxt',
  ],
  // Optional: feeds the dialog editor's autocomplete from your content collections.
  dialogEditor: {
    autocomplete: {
      items: { collection: 'entities', field: 'templateId', where: { type: 'item' } },
      abilities: { collection: 'abilities', field: 'abilityId' },
      statusEffects: { collection: 'statusEffect', field: 'statusEffectId' },
      classes: { collection: 'classes', field: 'classId' },
    },
  },
  css: ['~/assets/css/main.css'],
  compatibilityDate: '2025-01-01',
  // The HUD uses these semantic colors; declare them or Nuxt UI drops the classes.
  ui: {
    theme: {
      colors: ['primary', 'secondary', 'success', 'error', 'warning'],
    },
  },
  build: {
    // Both packages ship .vue/.ts source. The host app compiles them.
    transpile: ['@artificer-forge/engine', '@artificer-forge/assets'],
  },
  // Custom SVG icon set used by the action bar and panels (prefix `af`).
  icon: {
    customCollections: [{
      prefix: 'af',
      dir: resolve('./assets/icons'),
    }],
  },
})
```

```css [assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
/* Registers the engine's HUD/scene component utility classes (self-contained @source). */
@import "@artificer-forge/engine/styles.css";
```

::

### Why `build.transpile`?

The engine's `exports` map points straight at `./src/index.ts` and `.vue` files. Nothing is pre-bundled. Without `transpile`, Node tries to import `.vue` files directly and the build fails. The assets package needs the same treatment for its `/nuxt` module entry.

::warning
`build.transpile: ['@artificer-forge/engine', '@artificer-forge/assets']` is mandatory.
::

### Why the styles import?

The host's Tailwind must scan the engine source to generate the utility classes the HUD uses. `@artificer-forge/engine/styles.css` contains one line:

```css
@source "./src/**/*.{vue,ts}";
```

The `@source` path resolves relative to the engine package, so it works from any app location.

## Plugins

Two Nuxt plugins connect app data to the engine. Both live in `apps/playground/plugins/`.

### Content source (`gameData.ts`)

The engine fetches nothing. `useGameStore().configureContent()` must run before the first `spawnFromTemplate` or `loadScene`, or the store throws `[game] content source not configured`. A plugin is the right place because it runs before any page.

```ts [plugins/gameData.ts]
import {
  type DamageTypeDefinition,
  type EntityTemplate,
  type SceneDef,
  type StatusEffectDefinition,
  useDamageTypeStore,
  useGameStore,
  useStatusEffectStore,
} from '@artificer-forge/engine/runtime'

export default defineNuxtPlugin(async () => {
  const gameStore = useGameStore()

  gameStore.configureContent({
    resolveTemplate: templateId =>
      queryCollection('entities').where('templateId', '=', templateId).first() as unknown as Promise<EntityTemplate | null>,
    resolveScene: sceneId =>
      queryCollection('scenes').where('sceneId', '=', sceneId).first() as unknown as Promise<SceneDef | null>,
    resolveAbility: abilityId =>
      queryCollection('abilities').where('abilityId', '=', abilityId).first(),
    resolveDialog: dialogId =>
      queryCollection('dialogs').where('dialogId', '=', dialogId).first(),
    resolveClass: classId =>
      queryCollection('classes').where('classId', '=', classId).first(),
  })

  // Damage types and status effects are content too; load them once.
  await Promise.all([
    useDamageTypeStore().load(() => queryCollection('damageType').all() as unknown as Promise<DamageTypeDefinition[]>),
    useStatusEffectStore().load(() => queryCollection('statusEffect').all() as unknown as Promise<StatusEffectDefinition[]>),
  ])
})
```

See [Game Store: content source](/core-concepts/game-store#content-source) for the `ContentSource` contract.

### Modular parts (`modularParts.ts`)

Modular characters need the part manifest generated by the assets module. The plugin hands it to the engine and registers named segment materials (used by `appearance.segmentMaterials`, for example Cedric's ghost arm).

```ts [plugins/modularParts.ts]
import manifest from '#build/character-parts.mjs'
import { registerPartManifest, registerSegmentMaterials } from '@artificer-forge/engine/runtime'
import { ghostMaterial, type GhostMaterialOptions } from '@artificer-forge/vfx'

export default defineNuxtPlugin(() => {
  registerPartManifest({
    rigs: manifest.rigs,
    parts: [
      ...manifest.bodies,
      ...manifest.heads,
      ...manifest.hair,
      ...manifest.beards,
      ...manifest.eyebrows,
      ...manifest.horns,
    ],
  })

  registerSegmentMaterials({
    ghost: (params, { isWebGPU }) => {
      const opts = (params ?? {}) as GhostMaterialOptions
      if (isWebGPU) return ghostMaterial(opts).material
      // WebGL fallback: translucent tint
      // ...
    },
  })
})
```

Armor assets are not in the manifest. They resolve through item YAML (`modular.assets`). See [Modular Characters](/characters/modular-characters).

## Peer Dependencies

The engine declares these peers. The workspace catalog (`pnpm-workspace.yaml`) pins the actual versions.

| Package | Engine range | Workspace version | Notes |
|---------|--------------|-------------------|-------|
| `@tresjs/core` | `>=5.0.0` | `5.8.1` | |
| `@tresjs/cientos` | `>=5.0.0` | `5.7.0` | |
| `three` | `>=0.170.0` | `^0.183.2` | `@artificer-forge/post-processing` requires `^0.183.0`. Its `ScaledDepthOfFieldNode` overrides internals of `DepthOfFieldNode` and throws on a different version |
| `vue` | `>=3.4.0` | `^3.5.30` | |
| `pinia` | `>=3.0.0` | `^3.0.4` | Game state |
| `@vueuse/core` | `>=12.0.0` | `^14.2.1` | |
| `@nuxt/ui` | `>=4.0.0` | `^4.5.1` | **Optional**. Only for `@artificer-forge/engine/ui` |

::caution
Treat `three` as pinned to `0.183.x`. The engine's `>=0.170` range is wider than what its post-processing dependency accepts.
::
