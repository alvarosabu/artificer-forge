Wind is a small TSL module that every vegetation component embeds. Each component owns one set of wind uniforms, advances them in its own `onBeforeRender`, and samples `windOffset` in its vertex shader. Direction and strength arrive as props (`windAngle`, `windStrength`), usually bound to the [environment store](/environment/environment-store). The noise-driven sway is adapted from Bruno Simon's Folio 2025.

```ts
import {
  createWindUniforms, windOffset, advanceWindTime,
  DEFAULT_WIND_ANGLE, DEFAULT_WIND_STRENGTH, DEFAULT_WIND_TIME_FREQUENCY,
  WindLines, createWindLines, spawnWindLine, updateWindLines,
} from '@artificer-forge/engine/runtime'
import type { WindSettings, WindUniforms, WindLinesOptions } from '@artificer-forge/engine/runtime'
```

## `WindSettings`

Every vegetation options interface (`FoliageOptions`, `GrassOptions`, `GrassTuftsOptions`, `FlowersOptions`) extends it, so the same three props exist on every component:

| Name | Type | Default | Purpose |
|------|------|---------|---------|
| `windAngle` | `number` | `DEFAULT_WIND_ANGLE` = `Math.PI * 0.6` | Direction in radians. The XZ direction is `(sin(angle), cos(angle))` |
| `windStrength` | `number` | `DEFAULT_WIND_STRENGTH` = `0.5` | 0..1. Scales the offset AND the speed of time |
| `windTimeFrequency` | `number` | `DEFAULT_WIND_TIME_FREQUENCY` = `0.5` | Base scroll speed of the noise |

## `createWindUniforms(settings)`

```ts
function createWindUniforms(settings?: WindSettings): WindUniforms
```

| Uniform | Type | Initial | Purpose |
|---------|------|---------|---------|
| `direction` | `vec2` | `(sin(angle), cos(angle))` | Unit XZ direction |
| `positionFrequency` | `float` | `0.5` | World-space scale of the noise |
| `strength` | `float` | `windStrength` | Offset amplitude |
| `timeFrequency` | `float` | `windTimeFrequency` | Scroll speed |
| `localTime` | `float` | `0` | Accumulated by `advanceWindTime` |

Components update `direction` and `strength` from prop watchers:

```ts
watch(() => props.windAngle, (angle) => uniforms.wind.direction.value.set(Math.sin(angle), Math.cos(angle)))
watch(() => props.windStrength, (val) => { uniforms.wind.strength.value = val })
```

## `advanceWindTime(wind, delta)`

```ts
wind.localTime.value += delta * wind.timeFrequency.value * wind.strength.value
```

Time is scaled by strength, so a strong wind also moves faster, not only further. Each component calls this in its own `useLoop().onBeforeRender`; there is no global wind clock.

## `windOffset(wind)`

```ts
const offset = windOffset(wind)          // TSL Fn
const xz = offset(positionWorld.xz)      // Node<'vec2'>
```

Two octaves of `mx_noise_float`, scrolled along `direction` by `localTime`:

- octave 1 at `p * 0.2`, full time speed
- octave 2 at `p * 0.1`, `0.2×` time speed, half weight

The octaves MUST keep different frequencies and time scales, or the wind reads as one marching wave. A constant `+0.4` is added before scaling: real wind bows vegetation downwind, it does not oscillate it around the rest pose. The result is `direction * intensity * strength`.

How the consumers apply it (the multipliers are what make each species read differently):

| Component | Applies `windOffset` to |
|-----------|-------------------------|
| Foliage | Rotates each leaf quad in-plane by `length(offset) * 2.2` (flutter), never the UV |
| Grass | Offset `* height * 2 * windWeight`, plus a droop `|w|² / 2h` so blades bend instead of stretching |
| GrassTufts | Offset `* height * 1.4 * bladeT` |
| Flowers | Offset `* stemHeight * 1.8 * windWeight` |

## `<WindLines>`

Faint ribbons that travel downwind, one pool of meshes spawned on a random interval. They are the only visible hint of wind over bare ground.

```vue
<WindLines
  :wind-angle="environment.windAngle"
  :intensity="environment.windStrength"
  :radius="15"
  :height="2"
/>
```

### Props

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `count` | `number` | `4` | Pool size. A full pool drops new spawns (backpressure, no queue) |
| `color` | `TresColor` | `'#ffffff'` | Ribbon colour (live) |
| `thickness` | `number` | `0.1` | Max ribbon half-width (live) |
| `opacity` | `number` | `0.35` | Constant opacity (live); the travel fade is done with thickness |
| `length` | `number` | `10` | Curve length along Z |
| `handlesCount` | `number` | `4` | Catmull-Rom control points; alternating up/down gives an S-wave |
| `amplitude` | `number` | `1` | Vertical amplitude of the S-wave |
| `divisions` | `number` | `30` | Curve samples per ribbon |
| `intervalMin` | `number` | `0.3` | Seconds between spawns, lower bound |
| `intervalMax` | `number` | `2` | Upper bound |
| `translation` | `number` | `1` | World distance a line drifts downwind over its life |
| `windAngle` | `number` | `DEFAULT_WIND_ANGLE` | Spawn yaw and drift direction |
| `intensity` | `number` | `DEFAULT_WIND_STRENGTH` | 0..1. Remapped to a duration of 8 s (calm) down to 2 s (strong) |
| `originX` | `number` | `0` | Spawn area centre |
| `originZ` | `number` | `0` | |
| `radius` | `number` | `15` | Spawn within `± radius` of the origin |
| `height` | `number` | `2` | Spawn height |

Only `color`, `thickness` and `opacity` are watched. Geometry props (`count`, `length`, `handlesCount`, `amplitude`, `divisions`) are read once by `createWindLines`, so changing them needs a remount.

### Factory API

```ts
const { lines, uniforms, dispose } = createWindLines(options)   // hidden pool, one geometry, one material per line
spawnWindLine(lines, { originX, originZ, radius, height, windAngle, intensity }, random?) // boolean, false when the pool is full
updateWindLines(lines, delta, translation)                       // advance progress, drift, free finished lines
```

The ribbon geometry duplicates every curve point; the vertex shader pushes even and odd vertices to opposite sides (`vertexIndex % 2`) along a constant world tangent `(0, 1, -1)`. Thickness is `baseThickness * progressThickness`: zero at both ends of the curve, and a `±1` wide window that travels along `ratio` as `progress` goes 0..1.

`WindLines.vue` replaces the source's recursive `setTimeout` with elapsed-time accumulation inside `onBeforeRender`: no timer to leak on unmount, and the spawns pause with the render loop.

## Gotchas

::warning
- **The ribbon tangent is a world-space constant.** `(0, 1, -1)` works for the game's constrained camera. A free-orbit camera sees the ribbons edge-on from some angles; that needs a screen-space offset.
- **Wind is per component.** Two `<Grass>` fields with the same props produce the same motion only because they receive the same `windAngle`/`windStrength` and both start `localTime` at 0. There is no shared clock to desync from.
- **`strength` also scales time.** Setting `windStrength` to `0` freezes the noise scroll as well as the amplitude.
- **Spawns drop, they do not queue.** With `count: 4` and `intervalMin: 0.3`, a strong wind (2 s lines) spawns faster than lines free up. That is intended.
::
