Trees in a level are two things: a trunk mesh that ships in the GLB and a canopy that is generated at runtime. In Blender the canopy is authored as plain icospheres named `Tree_Cannopy_*`, invisible at runtime, there only to carry a position and a radius. `extractCanopyReferences` reads those markers into `Object3D` references, and `<Trees>` feeds them to [Foliage](/environment/foliage) with the scale corrected for how a cluster actually grows.

```ts
import { Trees, extractCanopyReferences } from '@artificer-forge/engine/runtime'
import type { CanopyExtractOptions } from '@artificer-forge/engine/runtime'
```

## Usage

Trimmed from `apps/playground/pages/environment/terrain/experience.vue`:

```vue
<script setup lang="ts">
import { Group, Mesh } from 'three'
import type { Object3D } from 'three'
import { extractCanopyReferences, Trees } from '@artificer-forge/engine/runtime'

const { state: gltf } = useGLTF('/levels/level-512.glb', { draco: true })
const propsRoot = shallowRef<Object3D | null>(null)
const canopyReferences = shallowRef<Object3D[]>([])
const { state: foliageTexture } = useTexture('/textures/foliage/foliageSDF.png')

watch(gltf, (loaded) => {
  if (!loaded) return
  const ground = loaded.scene.getObjectByName('Terrain')

  // Clone rather than reparent: useGLTF caches the scene by url, and moving
  // nodes out of it would empty the cached copy on the next HMR pass.
  const scenery = new Group()
  for (const child of loaded.scene.children) {
    if (child !== ground) scenery.add(child.clone())
  }

  // Before propsRoot is published, or the grading watcher builds materials for
  // marker balls that are about to be removed.
  canopyReferences.value = extractCanopyReferences(scenery)
  propsRoot.value = scenery
}, { immediate: true })
</script>

<template>
  <primitive v-if="propsRoot" :object="propsRoot" />
  <Trees
    :references="canopyReferences"
    :foliage-texture="foliageTexture"
    :grading="grading"
    color-a="#6bd54d"
    color-b="#86b544"
    :amount="150"
    :leaf-size="0.5"
    :canopy-scale="1"
    :wind-angle="environment.windAngle"
    :wind-strength="environment.windStrength"
  />
</template>
```

## `extractCanopyReferences(root, options)`

```ts
function extractCanopyReferences(root: Object3D, options?: CanopyExtractOptions): Object3D[]
```

| Option | Type | Default | Purpose |
|--------|------|---------|---------|
| `namePrefix` | `string \| string[]` | `['Tree_Cannopy', 'Tree_Canopy']` | Matched with `startsWith` against the glTF NODE name |
| `detach` | `boolean` | `true` | Remove the markers from the scene graph so they never render |

Returns one `Object3D` per marker: `position` = blob centre, uniform `scale` = blob radius in metres, `updateMatrixWorld()` already called.

How it decides the radius: from the marker's BOUNDING SPHERE transformed by `matrixWorld`, not from the node transform. Blender's exporter bakes an object's location and scale into the vertices as soon as the transform is applied, so the testbed markers all arrive with an identity node matrix. Reading the node would pile every blob at the trunk origin with radius 1. The bounding sphere is the same answer when the transform IS live, so it works either way.

Two details that are easy to get wrong when writing your own:

- Markers are collected first and mutated after. `removeFromParent()` inside `traverse()` edits the children array being walked and skips siblings.
- Detach only, never dispose. `Object3D.clone()` shares geometry with the scene `useGLTF` holds in its cache; disposing here would blank the trees on the next load from that cache.

Both name spellings are default on purpose: the level was authored as `Cannopy`, and fixing the typo in Blender must not silently drop every canopy.

## `<Trees>` props

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `references` | `Object3D[]` | `[]` | Blob markers: position = centre, uniform scale = radius in metres |
| `foliageTexture` | `Texture \| null` | `undefined` | Leaf cutout |
| `colorA` | `TresColor` | `'#3c6b2f'` | Shadow side |
| `colorB` | `TresColor` | `'#86b544'` | Light side |
| `amount` | `number` | `150` | Leaf quads per blob. A tree carries more, smaller leaves than a bush |
| `leafSize` | `number` | `0.5` | Quad edge in metres at cluster scale 1 |
| `canopyScale` | `number` | `1` | Taste multiplier on the marker radius |
| `seed` | `string` | `'trees'` | |
| `lightingDirection` | `Vector3` | `undefined` | Ungraded ramp only |
| `grading` | `GradingContext \| null` | `null` | |
| `windAngle` / `windStrength` | `number` | defaults | |

### Scale correction

A marker's radius is the silhouette you want, but `Foliage`'s scale means something smaller: the cluster CORE reaches `scale * 1`, then leaf quads of `scale * leafSize` are billboarded around each anchor, so the blob really reaches `scale * (1 + leafSize / 2)`. Feeding the radius in raw overshoots by that much and the canopy swallows the trunk. `Trees.vue` divides it out:

```ts
const overshoot = 1 + props.leafSize / 2
cluster.scale.setScalar(reference.matrixWorld.getMaxScaleOnAxis() / overshoot * props.canopyScale)
```

### Remount on change

`createFoliage()` bakes the reference list into instance buffers and the leaf count into the geometry. `Trees.vue` keeps a `version` counter that bumps when `clusters`, `amount` or `seed` change and keys the inner `<Foliage>` on it, so level HMR and the leches sliders both land on a fresh component. Colours, wind and grading are live.

## Gotchas

::warning
- **Node name, not mesh name.** three.js copies the glTF NODE name onto `Mesh.name`. In `testbed.glb` the canopy nodes are `Tree_Cannopy_*` while their mesh datablocks are still `Tree_Bare_*.00n`. Rename the object in Blender, not the mesh.
- **Extract before grading.** Call `extractCanopyReferences` on the cloned scenery BEFORE publishing it to a watcher that runs `applyGradingToModel`, or the marker balls get graded materials built for nothing.
- **No trample map.** The trample squash pulls anchors toward y = 0, which is several metres below a canopy. `<Trees>` does not accept `trample`.
- **`references` with an identity matrix are fine.** The bounding-sphere path handles applied transforms. But every reference must have `matrixWorld` up to date; the extractor does that for you, a hand-built list must call `updateMatrixWorld()`.
::
