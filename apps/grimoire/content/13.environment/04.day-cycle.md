The day cycle is a 0..1 phase that loops. The engine provides the generic track math (interpolate presets along a loop, tween a phase the short way around). The playground owns the policy: the four `GradingProps` presets, the keyframe stops, and the `useDayCycle` composable that writes into the [environment store](/environment/environment-store) every frame.

```ts
// engine (mechanism)
import { createPresetTrack, createPhaseTween, lerpPresets, wrap01 } from '@artificer-forge/engine/runtime'

// playground (policy)
import { DAY_CYCLE_NAMES, DAY_CYCLE_STOPS, DAY_CYCLE_TRACK, dayCyclePresets } from '~/utils/dayCyclePresets'
const dayCycle = useDayCycle() // auto-imported composable
```

## Engine helpers (`runtime/grading/presetTrack.ts`)

The helpers know nothing about day or night. A weather system or a dungeon mood track uses the exact same primitive.

### `wrap01(v)`

Wraps any number into `[0, 1)`. `wrap01(-0.1)` is `0.9`.

### `lerpPresets(a, b, t, target?)`

```ts
function lerpPresets<T>(a: T, b: T, t: number, target?: T): T
```

Interpolates every key of a preset: numbers linearly, `Color` with `lerpColors`, `Vector3` with `lerpVectors`. Without `target` it clones `a` first. Pass a `target` in a render loop to avoid allocation (verified by `presetTrack.test.ts`, "writes into the provided target without allocating").

### `createPresetTrack(presets, stops)`

```ts
function createPresetTrack<T>(presets: T[], stops: number[]): { sample: (phase: number, target?: T) => T }
```

`stops` are the phases where each preset is exact. Between two stops the track lerps; after the last stop it wraps back to the first preset. Rules, enforced with a thrown `Error`:

- `presets` and `stops` have the same non-zero length
- `stops` are strictly ascending
- all stops are within `[0, 1)`

A single-preset track returns that preset at any phase.

### `createPhaseTween()`

```ts
const tween = createPhaseTween()
tween.start(fromPhase, toPhase, durationSeconds)
tween.tick(delta) // number while tweening, null when idle
tween.active      // boolean
```

Tweens a phase toward a target going the SHORT way around the loop: `0.9 → 0.1` goes forward through `1.0`, `0.1 → 0.9` goes backward. A zero duration, or a target equal to the start, leaves it idle.

## Playground presets (`apps/playground/utils/dayCyclePresets.ts`)

```ts
export const DAY_CYCLE_NAMES = ['day', 'dusk', 'night', 'dawn'] as const
export type DayCycleName = typeof DAY_CYCLE_NAMES[number]
export const DAY_CYCLE_STOPS = [0, 0.25, 0.35, 0.8]
```

`DAY_CYCLE_NAMES` and `DAY_CYCLE_STOPS` are parallel arrays: the stop is the canonical phase to jump to for a named look (the start of its plateau).

| Preset | `lightColor` | `lightIntensity` | `shadowColor` | `fogColorA` | `fogColorB` | `fogNearRatio` | `fogFarRatio` |
|--------|--------------|------------------|---------------|-------------|-------------|----------------|---------------|
| day | `#ffd2c2` | 1.2 | `#b4a0c8` | `#00ffff` | `#9b89ff` | 0.315 | 1.25 |
| dusk | `#ff8181` | 1.2 | `#4e009c` | `#3e53ff` | `#ff4ce4` | 0 | 1.25 |
| night | `#3240ff` | 1.6 | `#2f00db` | `#10266f` | `#490a42` | -0.85 | 1 |
| dawn | `#ffa882` | 1.2 | `#db004f` | `#f885ff` | `#ff7d24` | 0.3 | 1.25 |

All four share the static `lightDirection` `(-1, -1, -1).normalize()`. The sun orbit in `useDayCycle` overrides it.

The track holds day and night at two stops each, so an auto loop dwells on the stable looks instead of spending all its time mid-lerp:

```ts
export const DAY_CYCLE_TRACK = {
  presets: [day, day, dusk, night, night, dawn, day],
  stops:   [0,   0.15, 0.25, 0.35, 0.6,  0.8,  0.9],
}
```

Repeated entries reference the SAME preset object, so a live edit of `day` changes both of its stops.

## `useDayCycle()` (`apps/playground/composables/useDayCycle.ts`)

```ts
const { phase, setPhase, transitionTo, tick, sun, auto } = useDayCycle()
```

| Member | Type | Purpose |
|--------|------|---------|
| `phase` | `Ref<number>` | Current 0..1 phase |
| `setPhase(value)` | `(v: number) => void` | Scrub directly |
| `transitionTo(target, options?)` | `(target: DayCycleName \| number, { duration?: number }) => void` | Tween to a named stop or a raw phase. Default duration `2` s |
| `tick(delta)` | `(delta: number) => void` | Advance, sample, write `environment.setGrading` |
| `auto` | `{ running: boolean, duration: number }` | Automatic time. Defaults `running: true`, `duration: 240` (one loop per four minutes) |
| `sun` | `{ orbit, theta, phi, thetaAmplitude, phiAmplitude }` | Sun orbit shape. Defaults `true`, `Math.PI / 4`, `0.63`, `1.25`, `0.62` |

`tick` does, in order:

1. If a tween is active, take its phase (manual transitions win). Otherwise, if `auto.running`, advance `phase += delta / auto.duration`.
2. `track.sample(phase, current)` into one reusable `GradingProps` (no allocation).
3. `updateSun()` AFTER the sample, so the orbit overrides the presets' `lightDirection`.
4. `environment.setGrading(current)`.

Time is gameplay delta, not wall clock: pausing the render loop pauses the day.

### Sun orbit

The light direction comes from a continuous spherical path driven by the phase, not from lerping the preset vectors. A vector lerp cuts a chord through the sky dome and collapses toward zero length mid-transition. With `sun.orbit` on:

- `theta` (azimuth) sweeps `± thetaAmplitude` around `sun.theta`, so shadows rotate through the day
- `phi` rides a half-cosine: high at noon (short shadows), low at dawn and dusk (long shadows)
- `phi` is clamped to `[0.05, 1.45]`. Past `π/2` the sun is underground and the shadow map goes dark
- The sun peaks at phase 0 (the day stop) via `SUN_PHASE_OFFSET = 0.5`
- The spherical vector points scene → sun; grading wants light → scene, so it is negated

Set `sun.orbit = false` to use the presets' static direction.

## Usage

Trimmed from `apps/playground/pages/environment/day-cycle/experience.vue`:

```vue
<script setup lang="ts">
import { createGradingContext, useEnvironmentStore } from '@artificer-forge/engine/runtime'
import type { DayCycleName } from '~/utils/dayCyclePresets'

const environment = useEnvironmentStore()
const dayCycle = useDayCycle()
const grading = createGradingContext({ sceneNear: 12, sceneFar: 45 })

const { dayCyclePreset, dayCycleAuto, dayCycleDuration, dayCycleOrbit } = useControls('dayCycle', {
  preset: { value: 'day', options: [
    { text: 'Day', alias: 'day', value: 'day' },
    { text: 'Dusk', alias: 'dusk', value: 'dusk' },
    { text: 'Night', alias: 'night', value: 'night' },
    { text: 'Dawn', alias: 'dawn', value: 'dawn' },
  ] },
  auto: { value: dayCycle.auto.running, type: 'boolean' },
  duration: { value: dayCycle.auto.duration, min: 10, max: 600, step: 1, type: 'range' },
  orbit: { value: dayCycle.sun.orbit, type: 'boolean' },
}, { uuid })

// useDayCycle reads sun/auto every tick, so plain mutation works
watch(dayCyclePreset!, name => dayCycle.transitionTo(name as DayCycleName))
watch(dayCycleAuto!, (v) => { dayCycle.auto.running = v })
watch(dayCycleDuration!, (v) => { dayCycle.auto.duration = v })
watch(dayCycleOrbit!, (v) => { dayCycle.sun.orbit = v })

const { onBeforeRender } = useLoop()
onBeforeRender(({ delta }) => {
  environment.tickWind(delta)
  dayCycle.tick(delta)
  grading.sync(environment)
  syncLights() // shadow light copies environment.lightDirection / lightColor / lightIntensity
})
</script>
```

The terrain experience uses the same composable but starts with `dayCycle.auto.running = false` and only exposes the preset picker and the auto toggle.

## Gotchas

::warning
- **`tick` must run every frame**, even when scrubbing by hand. Sampling is cheap and it is what makes `setPhase` visible.
- **A manual transition wins over auto.** While a tween is active the auto clock is ignored; auto resumes from wherever the tween landed.
- **Stops are validated at construction.** Unsorted stops, a stop of `1`, or mismatched lengths throw when `createPresetTrack` is called, not when sampled.
- **Presets mutate in place.** `track.sample(phase, current)` writes into `current`, and `current.lightDirection` is then overwritten by the orbit. Do not keep a reference to it as if it were a snapshot.
- **Wall clock is not used.** `auto.duration` is in gameplay seconds. A slow frame advances the day by exactly that frame's delta.
::
