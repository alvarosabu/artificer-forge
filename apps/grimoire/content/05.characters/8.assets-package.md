`@artificer-forge/assets` (`packages/assets`) owns every shared 3D asset and generates the modular part manifest at build time. Both apps install its Nuxt module; nothing lives in an app's `public/` folder.

```ts
// apps/playground/nuxt.config.ts
export default defineNuxtConfig({
  modules: [/* … */, '@artificer-forge/assets/nuxt'],
  build: {
    transpile: ['@artificer-forge/engine', '@artificer-forge/assets'],
  },
})
```

## Package layout

```
packages/assets/
├── files/
│   ├── models/
│   │   ├── animations/Rig_{Medium,Large,Small}/   # 8 packs each
│   │   ├── characters/
│   │   │   ├── rig_medium.glb, rig_small.glb        # bare skeletons
│   │   │   ├── bodies/ heads/ hair/ beards/ eyebrows/ horns/ accessories/   # scanned slots
│   │   │   ├── armors/ trousers/ boots/ gauntlets/ cloaks/                  # item assets (not scanned)
│   │   │   ├── textures/                             # palette atlases
│   │   │   └── hero.glb, orc.glb, zynrae.glb, …      # legacy single-GLB characters
│   │   ├── interactables/Chest.glb
│   │   └── items/weapons/
│   └── textures/  grass/ foliage/ flipbook/ skybox/ electricity/
├── src/
│   ├── module.ts         # Nuxt module (./nuxt export)
│   ├── scan.ts           # build-time filesystem scan
│   ├── partManifest.ts   # types, filename parser, filters (root export)
│   └── partOverrides.ts  # PART_OVERRIDES
└── scripts/sync-blender.sh
```

Exports: `@artificer-forge/assets` (types + `parsePart`, `forSex`, `forRaceSex`, `RACE_RIG`, `SLOT_FOLDERS`, `PART_OVERRIDES`) and `@artificer-forge/assets/nuxt` (the module).

## What the module does

`src/module.ts`, `meta.name = '@artificer-forge/assets'`:

1. Pushes `files/` onto `nitro.publicAssets`, so `/models/…` and `/textures/…` URLs resolve in dev and in the build.
2. `addTemplate('character-parts.mjs')` with `scanParts(files/models/characters)` as its content. Import it as `#build/character-parts.mjs`.
3. `addTypeTemplate` declares that module:

```ts
declare module '#build/character-parts.mjs' {
  const manifest: {
    rigs: Record<'medium' | 'small', string>
    bodies: PartEntry[]; heads: PartEntry[]; hair: PartEntry[]; beards: PartEntry[]
    eyebrows: PartEntry[]; horns: PartEntry[]; accessories: PartEntry[]
  }
  export default manifest
}
```

4. Adds `files/models/characters/**` to `nuxt.options.watch`, so dropping a GLB into a slot folder reloads the dev server instead of needing a restart.

## The part manifest

`scanParts` reads the seven `SLOT_FOLDERS` (`bodies, heads, hair, beards, eyebrows, horns, accessories`), keeps `*.glb`, sorts, and parses each filename stem. The rigs are fixed:

```ts
rigs: {
  medium: '/models/characters/rig_medium.glb',
  small: '/models/characters/rig_small.glb',
}
```

Armor folders are skipped on purpose: armor assets are referenced from item YAML (`modular.assets`), not from the manifest ([Equipment](/characters/equipment)). Root-level GLBs (rigs, legacy characters) are not parts.

```ts
export interface PartEntry {
  id: string          // filename stem, also the mesh node name inside the GLB
  label: string       // "Human Male Cedric", "Long B", …
  path: string        // /models/characters/{folder}/{stem}.glb
  sex?: Sex           // omitted = unisex
  race?: Race[]       // omitted = any medium-rig race
  rig?: RigKey        // bodies only
  templateId?: string // armor only (reserved)
}
```

Filenames outside the convention are skipped with `[assets] Unparseable part filename, skipped: …`.

## Filename convention

`{RACE}_{SEX?}_{Part}_{Variant}`, KayKit style. `parsePart(stem, folder, overrides)`:

| Token | Rule |
|-------|------|
| Race prefix (first) | `HUM` human, `ELF` elf, `TIF` tiefling, `GOB` goblin, `GEN` any race (`race` omitted) |
| Sex (second, optional) | `M` or `F`. Positional, so a trailing `_F` variant letter or `MEDIUM` is never read as a sex |
| Size (bodies only) | ALL-CAPS `MEDIUM` / `SMALL` names the skeleton: `rig: 'small'` if the stem contains `SMALL`, else `'medium'` |
| Label | remaining tokens minus `Hair/Beard/Eyebrows/Head/Body/Horns/SMALL/MEDIUM`, title-cased; sexed race parts get a `Human Male …` prefix |

Examples from `files/models/characters/`:

| Stem | Parsed |
|------|--------|
| `HUM_M_MEDIUM_Body_A` | human, M, `rig: medium`, label "Human Male A" |
| `GOB_F_SMALL_Body_A` | goblin, F, `rig: small` |
| `HUM_M_Head_Cedric` | human, M, label "Human Male Cedric" |
| `GEN_M_Hair_Short_A` | any race, M |
| `GEN_Eyebrows_Thin_A` | any race, unisex |
| `TIF_Horns_A` | tiefling, unisex |
| `GOB_Piercing_A` | goblin, unisex (accessories folder) |

The current library: 4 bodies (`HUM_{M,F}_MEDIUM_Body_A`, `GOB_{M,F}_SMALL_Body_A`), 13 heads (HUM, ELF, GOB, TIF), 29 hair, 6 beards, 13 eyebrows, 4 horns, 4 accessories.

## Races and rigs

```ts
export type Race = 'human' | 'elf' | 'tiefling' | 'goblin'
export type RigKey = 'medium' | 'small'

export const RACE_RIG: Record<Race, RigKey> = {
  human: 'medium',
  elf: 'medium',
  tiefling: 'medium',
  goblin: 'small',
}
```

`GEN_` parts are authored on the medium rig, so "any race" means "any medium-rig race". Filters:

```ts
forSex(parts, sex)              // unisex or matching sex
forRaceSex(parts, race, sex)    // forSex, then: race-tagged parts must include race;
                                // untagged parts only for RACE_RIG[race] === 'medium'
```

A goblin therefore only sees `GOB_` heads, hair and eyebrows, never `GEN_` hair.

## `PART_OVERRIDES`

Exceptions the filename cannot express, merged over the parsed entry by id. Exceptions only; a part must still exist on disk to appear.

```ts
export const PART_OVERRIDES: Record<string, PartOverride> = {
  // Medium races share the human silhouettes until race-specific bodies exist.
  HUM_M_MEDIUM_Body_A: { race: ['human', 'elf', 'tiefling'] },
  HUM_F_MEDIUM_Body_A: { race: ['human', 'elf', 'tiefling'] },
  // Only M goblin hair/brows exist: let F goblins use them rather than go bald.
  GOB_M_Hair_Short_A: { sex: undefined },
  GOB_M_Eyebrows_Thick_A: { sex: undefined },
}
```

`PartOverride = Partial<Pick<PartEntry, 'label' | 'sex' | 'race'>>`.

## Consuming the manifest

The engine never imports `#build/character-parts.mjs`. The app hands the manifest over once:

```ts
// apps/playground/plugins/modularParts.ts
import manifest from '#build/character-parts.mjs'
import { registerPartManifest } from '@artificer-forge/engine/runtime'

registerPartManifest({
  rigs: manifest.rigs,
  parts: [...manifest.bodies, ...manifest.heads, ...manifest.hair, ...manifest.beards, ...manifest.eyebrows, ...manifest.horns],
})
```

Engine side (`runtime/modular/partRegistry.ts`):

```ts
export interface ModularPartRef { id: string, path: string, rig?: string }
export interface ModularPartManifest { rigs: Record<string, string>, parts: ModularPartRef[] }
export const DEFAULT_RIG_KEY = 'medium'

export function registerPartManifest(manifest: ModularPartManifest): void
export function resolvePartPath(id: string): string | undefined
export function resolvePartRig(id: string): string          // DEFAULT_RIG_KEY when the part names none
export function manifestRigPath(rigKey?: string): string | null
```

The flat `parts` list is enough for the engine; slot grouping is a picker concern. The playground's `utils/characterParts.ts` re-exports the grouped arrays (`BODIES`, `HEADS`, `HAIR`, …, `RIGS`) for the customizer.

::note
Adding a part: drop `{RACE}_{SEX}_{Part}_{Variant}.glb` into the matching slot folder, make sure its mesh node has the same name as the file and its materials are named `Skin` / `Hair` / `Horns` where tinting should apply. The dev server reloads and the part shows up in `/character/create`. Add a `PART_OVERRIDES` entry only for a race or sex exception.
::
