title: Model Loading
description: The two ways a character rig reaches the scene, a single Draco GLB through useGLTF or a modular assembly from the KayKit part library served by the assets package.
---

A character rig comes from one of two places. `Character` and `Actor` pick the path once at setup from `entity.appearance`:

| Path | When | Loader |
|------|------|--------|
| Single GLB | template has `model` + `rig` | `useGLTF(model, { draco: true })` from `@tresjs/cientos` |
| Modular | template has `appearance` | `useModularRig` + the shared `loadGltf` cache ([Modular characters](/characters/modular-characters)) |

Every GLB, animation pack and texture is served by `@artificer-forge/assets` ([Assets package](/characters/assets-package)); apps never copy models into their own `public/`.

## Path 1: single GLB

Trimmed from `Character.vue`:

```ts
import { useGLTF } from '@tresjs/cientos'

const rigKey = computed(() => entity.value?.rig ?? 'Rig_Medium')

function useSingleGltfRig() {
  const { state, nodes } = useGLTF(entity.value?.model ?? '', { draco: true })
  return {
    rig: computed(() => nodes.value?.[rigKey.value]),
    animations: computed(() => state.value?.animations ?? []),
  }
}
```

- `nodes` is the name → object dictionary of the loaded scene. The rig is the armature node named by the template's `rig` field (`Rig_Medium`, or `Rig_Large` for `fenrath.yaml`).
- `state.animations` are clips embedded in the GLB. They are handed to `useCharacterAnimations` as the third argument and merged with the shared packs.
- `{ draco: true }` is required: the character GLBs are Draco-compressed. cientos creates its own `DRACOLoader` per call.
- `useGLTF` reads the path once. It does not reload when `entity.model` changes, which is fine because an entity never changes model.

Render with `<primitive>` behind a `v-if`, because `nodes` is empty until the load resolves:

```vue
<TresGroup ref="characterRef">
  <primitive v-if="rig" :object="rig" />
</TresGroup>
```

The playground's single-GLB characters: `hero.glb`, `orc.glb`, `zynrae.glb`, `fenrath.glb`, `Knight.glb`, `Ranger.glb` in `packages/assets/files/models/characters/`. They are legacy exports; new characters are modular.

::note
`Character.vue` still carries a hardcoded demo: when the loaded GLB has a `Hero_ArmRight` node, mesh `Ranger_ArmRight_1` gets the `ghostMaterial` from `@artificer-forge/vfx`. Modular characters do the same thing in data with `appearance.segmentMaterials`.
::

## Path 2: modular assembly

```ts
import { useModularArmor, useModularRig } from '@artificer-forge/engine/runtime'

const modular = useModularRig(() => entity.value?.appearance, useModularArmor(() => props.entityId))
const rig = modular.rig   // ShallowRef<Object3D | undefined>
```

`useModularRig` loads the bare skeleton named by the body part (`rig_medium.glb` or `rig_small.glb`), then loads each part GLB through `loadGltf` (one shared Draco decoder, one parse per path), clones the skinned meshes and rebinds them to the skeleton by bone name. The armor list comes from the entity's equipped items. Full mechanics: [Modular characters](/characters/modular-characters).

Why not `useGLTF` for parts: cientos creates a fresh `DRACOLoader` (worker pool + WASM heap) per call. Loading a dozen parts per character that way exhausts WASM memory; `gltfCache.ts` keeps it to one decoder with a worker limit of 2.

## Rig size for animations

Both paths must tell `useCharacterAnimations` which animation packs to load:

```ts
const rigSize = computed<RigSize>(() => {
  if (!isModular) return rigKey.value.replace('Rig_', '') as RigSize          // 'Rig_Large' -> 'Large'
  const key = resolvePartRig(entity.value!.appearance!.body)                   // 'medium' | 'small'
  return (key[0]!.toUpperCase() + key.slice(1)) as RigSize                     // 'Medium' | 'Small'
})
```

Packs live at `/models/animations/Rig_{Medium|Large|Small}/`. See [Animations](/characters/animations).

## Exposing controls

`Character` exposes its animation and movement API with `defineExpose`, and the experience registers each instance with `useSceneRefs`:

```vue
<Character
  v-for="entity in gameStore.partyEntities"
  :key="entity.id"
  :ref="(el: any) => setCharacterRef(entity.id, el)"
  :entity-id="entity.id"
/>
```

```ts
const { getCharacterRef } = useSceneRefs()
getCharacterRef(entityId)?.play(AnimationName.MELEE_1H_ATTACK_CHOP)
```

The full exposed list is in [Rendering: exposed surface](/entities/rendering).

## Model sources

- **KayKit** character parts and animation packs: the modular library in `@artificer-forge/assets`. Filenames follow `{RACE}_{SEX}_{Part}_{Variant}` ([Assets package](/characters/assets-package)).
- Legacy single-GLB characters carry a `Rig_Medium` (or `Rig_Large`) armature with the same bone names, so the shared packs animate them too.
